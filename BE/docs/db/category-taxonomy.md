# 카테고리 분류 체계 (성별 → 대분류 → 소분류)

`category` 테이블의 **실제 시드 데이터**를 정리한 참고 문서. 테이블 구조(컬럼·제약)는
[`data-dictionary.md`](./data-dictionary.md)를 보고, 이 문서는 **ID가 실제로 무엇을
가리키는지**(값 매핑)를 확인할 때 쓴다.

- 시드 원본: `BE/src/main/resources/db/seed.sql`
- 관련 계획: `docs/plans/BE/SY022-category-taxonomy.md`
- ID는 **시드 삽입 순서에 고정**되어 있다 — 성별 → 대분류 → 소분류 순, 각 단계 안에서도
  아래 표 순서 그대로 삽입된다. `seed.sql`을 고치면(항목 추가/순서 변경) 이 문서도 함께 갱신할 것.

## 요약

| depth | 의미 | 개수 | ID 범위 |
| :---: | --- | :---: | --- |
| 1 | 성별 | 3 | 1 ~ 3 |
| 2 | 대분류 | 18 (성별당 6) | 4 ~ 21 |
| 3 | 소분류 | 90 (성별당 30) | 22 ~ 111 |

## 조회 방법

`GET /api/categories`(인증 불필요)가 위 전체 111개를 `id` 오름차순 평탄 리스트
(`id`, `parentId`, `name`, `depth`)로 반환한다. 트리 구성은 응답을 받는 쪽(FE/AI)이 한다 —
BE는 트리로 묶어 내려주지 않는다.

로컬에서 직접 확인하려면:

```bash
docker exec -i vintib-postgres psql -U postgres -d vintib \
  -c "SELECT id, name, depth, parent_id FROM category ORDER BY id;"
```

## 비고

- 영문 코드(MEN/OUTER/JACKET 등, `docs/requests/AI/003-category-taxonomy-confirmed.md`에서
  다룬 원 요청 문서에 있던 표기)는 DB 컬럼으로 저장하지 않는다 — `category.name`은 한글만
  가진다. 매핑은 이 문서의 id 기준으로 한다.
- 기존(2-depth, 성별 없음) 카테고리 데이터로 이미 시드된 로컬 DB는 재기동해도 자동으로
  안 바뀐다. `docker compose down -v` 후 재기동해야 이 문서의 ID로 맞춰진다.

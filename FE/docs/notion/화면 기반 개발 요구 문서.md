# VinTib 화면 기반 개발 요구사항 요약

## 1. 문서 개요

### 문서 목적

VinTib 화면 기반 개발 요구 문서를 프론트엔드 구현자가 빠르게 참조할 수 있도록 핵심 요구사항 중심으로 재구성한다. 화면별 반복 설명은 공통 요구사항으로 통합하고, 각 화면에는 구현에 직접 필요한 진입, 데이터, 입력, 동작, 상태, 예외만 남긴다.

### 문서 작성 범위

- 인증, 온보딩, 홈, 검색, 상품 조회/등록/관리, 라이브, 경매, 구매, 주문/배송/환불, 포인트, AI 시착, 마이페이지, 알림 화면
- 화면 이동, 주요 버튼, 입력 검증, API 연동 필요 데이터, 실시간 갱신, 권한/상태별 예외
- 확정되지 않은 정책은 기능 요구로 단정하지 않고 `7. 미확정 및 추가 확인 사항`에 분리

### 문서 활용 방법

- 공통 상태/검증/오류는 `3. 공통 개발 요구사항`을 우선 적용한다.
- 각 화면 구현 시 `4. 화면별 핵심 요구사항`에서 해당 화면의 입력, 표시 데이터, 동작, 상태만 확인한다.
- API URL은 첨부 문서에 명시된 제안만 기재했다. 실제 계약은 BE Swagger/API 계약 문서에서 확정해야 한다.
- `확인 필요`, `설계 제안`, 오탈자/충돌 항목은 개발 확정값으로 사용하지 않는다.

## 3. 공통 개발 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 공통 레이아웃 | Figma 기준 상단 헤더, 본문 컨테이너, 하단/보조 영역 구조를 유지한다. 공통 헤더/메뉴 설명은 화면별 반복하지 않는다. |
| 헤더 및 메뉴 | 알림, 설정, 프로필 진입 요소는 공통 컴포넌트로 처리한다. 보호 화면에서는 인증 상태에 따라 노출/이동을 제어한다. |
| 인증 상태 처리 | 보호 화면 진입 시 미로그인 또는 토큰 만료는 `AUTH_REQUIRED`로 처리하고 로그인 화면으로 이동한다. |
| 사용자 유형 처리 | 상품 등록, 라이브 개설, 판매자 주문/배송은 사업자/판매자 권한이 필요하다. 권한 없으면 `PERMISSION_DENIED` 안내를 표시한다. |
| 버튼 상태 | 필수 입력 미충족, 처리 중, 판매 완료, 경매 종료, 포인트 부족, 권한 없음 상태에서는 주요 CTA를 비활성화한다. |
| 입력 폼 검증 | 필수값, 형식, 길이, 숫자 범위, 파일 형식/용량/개수는 프론트에서 1차 검증하고 서버 오류는 필드 하단에 매핑한다. |
| 로딩 처리 | 화면 진입 조회는 skeleton 또는 로딩 상태를 표시한다. 제출/입찰/구매 요청 중에는 중복 클릭을 막는다. |
| 빈 데이터 처리 | 목록 결과가 없으면 빈 상태와 재검색/필터 변경/등록 CTA를 제공한다. 예시 데이터로 채우지 않는다. |
| 오류 처리 | 공통 오류는 `AUTH_REQUIRED`, `PERMISSION_DENIED`, `VALIDATION_ERROR`, `RESOURCE_NOT_FOUND`, `REQUEST_ALREADY_PROCESSED`, `PRODUCT_SOLD_OUT`, `AUCTION_CLOSED`, `POINT_INSUFFICIENT`, `REALTIME_CONNECTION_FAILED`, `INTERNAL_ERROR` 기준으로 처리한다. |
| 모달 및 토스트 | 성공은 토스트 또는 완료 화면, 취소/삭제/비공개/구매확정/환불은 확인 모달을 사용한다. 실패는 필드 오류 또는 상단/토스트 오류로 구분한다. |
| 이미지 업로드 | 상품, 사업자 인증, AI 시착, 환불 증빙은 파일 형식/용량/개수/개인정보 동의 정책이 확정되어야 한다. 업로드 실패와 재시도 상태를 제공한다. |
| 페이지 이동 | 중복되는 화면 이동은 라우팅 가드와 공통 네비게이션 핸들러로 관리한다. 비정상 접근 시 목록 또는 안전한 이전 화면으로 이동한다. |
| 반응형 처리 | Figma는 1440px 데스크톱 프레임 중심이다. 모바일/태블릿 breakpoint와 하단 네비게이션 여부는 미확정이다. |
| 접근 권한 처리 | 본인 상품 구매/입찰/팔로우/찜 허용 여부는 미확정이다. 확정 전에는 서버 응답 기준으로 비활성/오류 표시한다. |
| 실시간 처리 | 라이브/경매 상태는 서버 시간과 서버 이벤트를 기준으로 갱신한다. 클라이언트 타이머만으로 낙찰/종료를 확정하지 않는다. |

## 4. 화면별 핵심 요구사항

> 이 절의 각 화면 요구사항은 아래 `4.0 Figma 화면 요소 검수표`를 우선 기준으로 구현한다. 기존 요약에서 통합 표기한 항목이 있더라도, Figma에서 확인된 입력 필드, 선택 항목, 버튼, 검증 안내 문구는 임의로 생략하거나 대표 항목으로 합치지 않는다.
> 

### 4.0 Figma 화면 요소 검수표

#### `[AUTH-001] 이메일 회원가입`

**체크리스트**

- 입력 필드: 이름, 이메일, 비밀번호
- 선택형 UI: 전체 동의하기, 필수 서비스 이용약관 동의, 필수 개인정보 수집 및 이용 동의, 선택 마케팅 정보 수신 동의
- 버튼: 보기(약관별), 가입하기, 싸피어스로 가입하기, 로그인하기, 도움말, 이용약관, 개인정보처리방침
- 안내 및 검증 문구: `8자 이상, 영문/숫자/특수문자 조합`, `VinTib 서비스 이용을 위해 정보를 입력해주세요.`, `약관 동의`
- 화면 이동 요소: 가입하기, 싸피어스로 가입하기, 로그인하기
- 로딩/빈/오류 상태: 확인 필요
- 문서에 누락된 요소: 이름 필드, 비밀번호 보기 버튼, 약관별 보기 버튼, SSO 가입 버튼

# VinTib 프론트엔드 디자인 구현 규칙

> **문서 목적**
> 
> 
> 최종 Figma 디자인을 Vue 화면으로 구현할 때 프론트엔드 담당자마다 색상, 크기, 여백, 상태 표현이 달라지는 문제를 방지하기 위한 공통 기준이다.
> 
> **디자인 콘셉트**
> 
> **Vintage Editorial × Live Auction**
> 
> - 일반 화면: 빈티지 패션 편집숍의 절제된 에디토리얼 분위기
> - 라이브 화면: 어둡고 영상 중심의 몰입형 경매 화면
> - AI 시착: 결과 이미지 중심의 디지털 패션 스튜디오
> - 강한 색상은 기능별로 구분하여 제한적으로 사용

## 1. 구현 기본 원칙

### 1.1 디자인 값 작성 방식

- 색상은 **6자리 HEX 대문자**로 정의한다.
- 투명도가 필요할 때만 `rgba()`를 사용한다.
- 화면과 컴포넌트에서 HEX 값을 직접 반복하지 않고 CSS 변수를 사용한다.
- Figma 값과 코드 값의 이름을 역할 중심으로 작성한다.
- `green`, `red`, `purple`처럼 색 이름만 사용하지 않고 기능이 드러나는 이름을 사용한다.

```
/* 권장 */
background: var(--color-primary);
color: var(--color-text-inverse);

/* 지양 */
background: #294335;
color: white;
```

### 1.2 강한 색상의 역할

- **Forest Green**: 일반 화면의 주요 행동과 선택 상태
- **Red**: LIVE, 경매, 긴급, 위험 행동
- **Violet**: AI 시착 기능
- 한 컴포넌트 안에 강한 강조색을 여러 개 사용하지 않는다.
- 밝은 라임색을 사용하지 않는다.
- 보라색을 서비스 전체의 메인 색상으로 사용하지 않는다.

## 3. 타이포그래피

### 3.1 폰트

```
font-family: Pretendard, "Noto Sans KR", Inter, sans-serif;
```

- 일반 UI는 Pretendard를 기본으로 사용한다.
- Pretendard 사용이 어려운 환경에서는 Noto Sans KR을 사용한다.
- 숫자는 Inter를 대체 폰트로 사용한다.
- `Noto Serif KR`은 메인 Hero와 에디토리얼 컬렉션 제목처럼 지정된 영역에만 사용한다.
- 버튼, 입력창, 표, 상품명에는 세리프 폰트를 사용하지 않는다.

### 3.2 타입 스케일

| 용도 | 크기 | 줄 높이 | 굵기 |
| --- | --- | --- | --- |
| Display | 48px | 60px | 700 |
| 페이지 제목 | 36px | 48px | 700 |
| 섹션 제목 | 26px | 36px | 700 |
| 카드 제목 | 17px | 24px | 600 |
| 본문 | 15px | 24px | 400 |
| 버튼 | 15px | 20px | 600 |
| 설명·캡션 | 13px | 18px | 400 |
| 상태 배지 | 12px | 16px | 600 |
| 경매 가격 | 32px | 40px | 700 |
| 경매 타이머 | 30px | 36px | 700 |

가격, 포인트, 타이머, 주문번호, 정산 금액에는 고정 폭 숫자를 적용한다.

```
font-variant-numeric: tabular-nums;
```

## 4. 레이아웃과 여백

### 4.1 데스크톱 기준

| 항목 | 기준 |
| --- | --- |
| 기본 Frame | 1440px |
| 최소 화면 높이 | 900px |
| 중앙 콘텐츠 최대 너비 | 1320px |
| Grid | 12 Columns |
| 바깥 여백 | 48~60px |
| Column Gutter | 24px |
| 기본 간격 단위 | 8px |
- 개발은 Desktop First로 진행한다.
- 1280px 데스크톱에서도 주요 콘텐츠가 깨지지 않도록 한다.
- 필요 화면은 1024px 가로형 태블릿까지 검토한다.
- 일반 화면은 중앙 콘텐츠 폭을 유지하고 지나치게 넓게 늘리지 않는다.
- 라이브 화면은 영상과 채팅·경매 패널의 정보 우선순위를 유지한다.

### 4.2 간격 토큰

```
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 20px;
  --space-6: 24px;
  --space-8: 32px;
  --space-10: 40px;
  --space-12: 48px;
  --space-16: 64px;
}

작은 요소 간격: 8~12px

카드 내부 여백: 16~24px

카드 사이 간격: 20~24px

큰 섹션 사이: 48~64px

의미 없는 17px, 27px처럼 임의의 값을 반복하지 않는다.
```

## 5. Radius와 Shadow

### 5.1 Radius

```
:root {
  --radius-control: 8px;
  --radius-card: 12px;
  --radius-media: 16px;
  --radius-modal: 16px;
  --radius-badge: 4px;
  --radius-chip: 999px;
}
```

| 요소 | Radius |
| --- | --- |
| 입력창·버튼 | 8px |
| 일반 카드 | 12px |
| 큰 이미지·미디어 | 16px |
| 모달·Drawer | 16px |
| 상태 배지 | 4px |
| 필터 칩 | 999px |
- Primary 버튼을 알약 형태로 만들지 않는다.
- 상태 배지는 작은 의류 라벨처럼 사각형에 가깝게 표현한다.
- 필터와 카테고리 선택만 둥근 칩 형태를 사용한다.
- 카드에는 무거운 그림자를 사용하지 않는다.
- 기본적으로 Border로 영역을 구분하고, Dropdown·Modal처럼 떠 있는 요소에만 약한 Shadow를 사용한다.

## 6. 버튼 규칙

### 6.1 버튼 종류

| 종류 | 용도 | 색상 |
| --- | --- | --- |
| Primary | 일반 화면의 핵심 행동 | Forest Green |
| Secondary | 보조 행동 | Neutral Outline |
| Tertiary | 중요도가 낮은 행동 | Text |
| Bid | 입찰 | Auction Red |
| AI | AI 시착 | Violet Outline 또는 Soft |
| Destructive | 삭제·취소 등 위험 행동 | Red |
| Disabled | 실행 불가 | Muted Gray |

### 6.2 버튼 높이

```
:root {
  --button-height-small: 36px;
  --button-height-standard: 48px;
  --button-height-major: 52px;
  --button-height-bid: 60px;
}
```

- 작은 버튼: 36px
- 일반 버튼: 48px
- 주요 CTA: 52px
- 입찰 CTA: 60px
- 아이콘 버튼의 최소 클릭 영역: 40×40px
- 버튼에는 Default, Hover, Pressed, Focus, Disabled, Loading 상태를 구현한다.
- Loading 중 버튼 너비가 변하지 않도록 한다.
- 입찰 버튼은 가능하면 다음 입찰가를 함께 보여준다.

## 7. 입력창과 폼

- 기본 높이는 48px로 통일한다.
- 입력창, Select, Date Picker의 높이와 Radius를 통일한다.
- Label, 입력 영역, 도움말 또는 오류 메시지를 하나의 단위로 구성한다.
- Placeholder는 Label을 대신하지 않는다.
- 오류는 Border 색상과 메시지를 함께 사용한다.
- Focus 상태는 키보드 사용자가 알아볼 수 있도록 명확히 표시한다.
- Disabled와 Readonly 상태를 시각적으로 구분한다.
- 상품 등록처럼 입력 항목이 많은 화면은 단계별 흐름을 유지한다.

## 8. 카드와 이미지

### 8.1 상품 카드

- 상품 이미지가 가장 먼저 보이도록 구성한다.
- 이미지 비율은 **4:5**를 기본으로 한다.
- 정보 순서는 이미지 → 상태 → 상품명 → 가격·포인트 → 판매자 순으로 통일한다.
- 상품 설명을 카드에 길게 노출하지 않는다.
- 찜 버튼은 이미지 위 동일 위치에 배치한다.
- Hover 시 과도하게 떠오르지 않고 Border 또는 미세한 이동만 사용한다.

### 8.2 라이브 카드

- 대표 이미지 비율은 기본 **16:9**로 사용한다.
- 판매자, 방송 제목, LIVE·예정 상태, 시청자 또는 예정 시간을 함께 표시한다.
- LIVE 카드 전체를 빨간색으로 채우거나 계속 깜빡이게 하지 않는다.
- 작은 LIVE 배지와 필요한 경우 미세한 상태 점만 사용한다.

### 8.3 프로필과 기타 이미지

| 이미지 | 비율 |
| --- | --- |
| 상품 이미지 | 4:5 |
| 라이브 대표 이미지 | 16:9 |
| 프로필 | 1:1 |
| AI 시착 결과 | 원본 비율 유지, 결과 중심 |
| 메인 Hero | 화면 시안 기준 |
- 이미지가 없을 때 사용하는 Placeholder를 통일한다.
- 이미지에는 목적에 맞는 `alt`를 작성한다.

## 9. 배지·필터·탭

### 9.1 상태 배지

| 상태 | 표현 |
| --- | --- |
| LIVE | Live Red 배경 + 흰 글자 |
| 경매 진행 중 | Auction Red |
| 경매 예정 | Neutral 또는 Auction Soft |
| 바로 구매 | Primary Text 또는 Forest Green |
| AI 시착 가능 | AI Violet |
| 판매 완료 | Muted Gray |
| 인증 완료 | Forest Green 아이콘 + 텍스트 |
- 상태 배지 Radius는 4px를 사용한다.
- 색상만으로 상태를 구분하지 않고 텍스트 또는 아이콘을 함께 제공한다.

### 9.2 필터 칩

- Radius는 999px를 사용한다.
- 선택 상태는 Forest Green Soft 배경과 Primary 색상으로 표현한다.
- 필터 칩을 Primary CTA처럼 강하게 보이게 하지 않는다.

### 9.3 탭

- 활성 탭 위치와 선택 상태가 명확해야 한다.
- 활성 상태 표현을 화면마다 다르게 만들지 않는다.
- 탭 전환 중 레이아웃이 크게 흔들리지 않도록 한다.

## 10. 일반 화면과 라이브 화면 구분

### 10.1 일반 탐색·거래 화면

- 밝은 Ivory·White 기반
- Charcoal 계열 텍스트
- Forest Green을 주요 CTA로 사용
- 이미지 중심의 편집숍 분위기
- 신뢰가 필요한 상품·거래 정보는 충분한 여백과 Border로 정리

### 10.2 라이브 시청·판매자 진행 화면

- `-color-live-background`를 기본 배경으로 사용
- 영상 영역을 가장 우선한다.
- 채팅, 상품, 경매 패널은 Dark Surface로 구분한다.
- 입찰 행동만 Auction Red로 강하게 강조한다.
- 일반 이동 버튼까지 Red로 만들지 않는다.
- AI 시착을 열어도 라이브 영상 맥락이 완전히 사라지지 않도록 한다.

### 10.3 AI 시착

- Violet은 AI 기능에서만 사용한다.
- 설명보다 업로드 이미지와 결과 이미지를 중심으로 구성한다.
- 생성 중, 완료, 실패 상태를 구분한다.
- AI 기능을 일반 Primary CTA보다 항상 강하게 강조하지 않는다.

## 12. 아이콘과 접근성

- 아이콘은 한 가지 라이브러리와 동일한 Stroke 스타일로 통일한다.
- 아이콘 크기는 주로 20px 또는 24px를 사용한다.
- 중요한 아이콘 버튼에는 Tooltip 또는 `aria-label`을 제공한다.
- 최소 클릭 영역은 40×40px로 유지한다.
- 색상만으로 선택·오류·상태를 표현하지 않는다.
- 키보드 Focus 표시를 제거하지 않는다.
- 본문과 배경의 대비를 충분히 유지한다.
- 의미 있는 이미지에는 `alt`를 작성한다.
- 클릭 요소는 가능한 한 `div` 대신 `button`, `a`, `input` 등 올바른 HTML 요소를 사용한다.

# AUCT-003~006 채팅·경매 패널 UI 요구사항

## 화면 목표

라이브 시청 화면에서 채팅과 실시간 경매 정보를 Figma와 같은 우선순위로 확인하고,
실제 서버 연동 전에도 더미 상태로 입력·반응·입찰 CTA를 검증한다.

## 기준 자료

- Figma 배포 프로토타입 라이브 시청 화면
- `docs/notion/화면 기반 개발 요구 문서.md`
- `docs/notion/기능 정의서.md`
- `docs/notion/프론트엔드 디자인 구현 규칙.md`
- `.codex/requests/be/012-live-watch-detail-contract-gaps.md`

## 채팅 UI

- 영상 왼쪽 중앙에 하트·불·박수·놀람 반응 버튼을 세로로 표시한다.
- 영상 왼쪽 하단에 작성자, 메시지 본문과 스크롤 가능한 더미 목록을 표시한다.
- 판매자 메시지는 별도 색상으로 구분한다.
- 입력창은 공백 입력을 전송하지 않으며 200자로 제한한다.
- 라이브 상태에서는 전송한 내용을 로컬 목록에 추가하고, 예정·종료 상태에서는 비활성화한다.

## 경매 UI

- 현재 입찰가, 다음 입찰가, 남은 시간, 최고 입찰자와 사용 가능 포인트를 표시한다.
- 입찰 CTA에는 모든 사용자에게 동일하게 보일 다음 입찰가를 포함한다.
- mock 입찰 처리 중에는 버튼을 비활성화해 중복 클릭을 막는다.
- mock 입찰 성공 후 최고 입찰자를 `나`로 표시하고 다음 연속 입찰을 제한한다.
- 포인트 부족, 예정, 종료·취소와 경매 상품 없음 상태에서는 사유를 CTA 문구로 표시한다.
- 금액과 타이머는 고정 폭 숫자를 사용하고 입찰 CTA만 Auction Red로 강조한다.

## Mock 상태

| query | 표시 |
| --- | --- |
| 없음 또는 `auction=BIDDABLE` | 입찰 가능 |
| `auction=PENDING` | 입찰 처리 중 |
| `auction=LEADING` | 현재 최고 입찰자·연속 입찰 제한 |
| `auction=INSUFFICIENT_POINTS` | 포인트 부족 |
| `mock=scheduled` | 경매 시작 전 |
| `mock=ended` | 종료된 경매 |
| `mock=empty-products` | 경매 상품 없음 |

## API 경계

실제 연결에 필요한 채팅 STOMP, 과거 메시지 조회, 경매 snapshot·입찰·입찰 내역·낙찰 결과와
reaction event 계약은 `012-live-watch-detail-contract-gaps.md`에 이미 정리돼 있다.
이번 작업은 별도 API를 호출하지 않으며 화면 데이터는 mock 전용 타입과 상수로 관리한다.

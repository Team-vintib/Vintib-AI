# 카테고리 판별 — 성별 축은 AI가 아니라 등록 폼에서 받아 주세요

- **요청자 파트**: AI
- **대상 파트**: BE (FE도 함께 확인 필요)
- **관련 문서**: `BE/docs/db/category-taxonomy.md` "사용 방법" 절

## 배경/이유

`category-taxonomy.md`의 "사용 방법"에 **"AI: 대분류 id(4~23)로 결과를 준다. 성별도 함께
판별해야 한다"** 고 적혀 있는데, 이건 2026-08-01에 확정했던 내용(성별은 사용자가 등록 폼에서
직접 선택)과 반대입니다. AI 쪽 코드(`AI/validation/CLASS/product-info-check/taxonomy.py`,
`worker/models/product_classifier/taxonomy.py`)는 그 확정에 맞춰 작성돼 있습니다.

성별을 AI가 판별하기 어렵다고 보는 이유 2가지입니다:

1. **원리적으로 판별 불가능한 케이스가 많습니다.** 바닥에 펼쳐놓고 찍은 티셔츠·데님·후드는
   남성복인지 여성복인지 사진만으로 구분되지 않습니다. UNISEX 카테고리가 존재하는 이유이기도
   하고, 실제로 저희 검증 정답셋 17장 중 대다수가 여기에 해당합니다.
2. **검증할 방법이 없습니다.** 지금 정답셋에 성별 라벨이 0건이라, 성별 판별을 붙여도 정확도를
   잴 수가 없습니다. 라벨링부터 새로 해야 하는데 위 1번 때문에 라벨러 간 일치도 자체가
   낮게 나올 가능성이 큽니다.

잘못 판별하면 FE가 **틀린 성별의 소분류 목록**을 보여주게 되어(예: 남성 아우터 5종 vs 여성
아우터 5종은 id가 다름) 사용자가 매번 고쳐야 합니다.

## 요청 내용

1. **등록 폼에서 성별(MEN/WOMEN/UNISEX)을 사용자가 먼저 고르게 해 주세요.** AI 분류 요청 시
   그 값을 함께 넘겨주시면, AI는 (성별 + 판별한 대분류) 조합으로 **대분류 id(4~23)를 그대로
   돌려드립니다** — 문서에 적힌 응답 계약 자체는 바뀌지 않습니다.
2. 성별을 못 받는 흐름이 있다면 알려 주세요. 그 경우 **UNISEX(id 17~23)로 고정 응답**하고
   사용자가 폼에서 바꾸는 방식으로 맞추겠습니다.
3. 위 1·2 중 어느 쪽으로 갈지 정해지면 `category-taxonomy.md`의 "사용 방법" 문구도 함께
   고쳐 주세요 — 지금 문구대로면 AI가 성별을 판별하는 것으로 읽힙니다.

## 참고 — AI 쪽 현재 구현

taxonomy는 2026-08-03에 새 시드(소분류 35종 / 대분류 20행 / depth3 103행)로 갱신 완료했고,
ID 매핑은 문서 표의 실제 값으로 assert 검산합니다(남성엔 원피스·점프슈트가 없어 성별별
블록 크기가 33/35/35로 다른 것까지 반영).

분류 파이프라인은 이렇습니다:

```
이미지 -> 소분류 35-way 예측 -> major_of() 로 대분류 역산 -> (폼 성별 + 대분류) -> depth2 id
```

소분류로 물어본 뒤 대분류로 접는 이유는 실측 때문입니다 — 대분류 6-way를 직접 물으면
정확도 0.35인데, 소분류로 물어서 접으면 1.00입니다(`AI/validation/CLASS/product-info-check/
REPORT.md` §14, §2-1). 추론 비용은 동일합니다.

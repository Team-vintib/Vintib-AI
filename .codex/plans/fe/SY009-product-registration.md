# 상품 등록 UI 및 등록 플로우

## 배경/목표

`/products/new` placeholder를 실제 `PROD-001~003` 상품 등록 화면으로 교체한다. 상품 사진과 기본 정보, 사이즈/소재, 상태/하자, AI 품질 검증, 가격, 검토, 완료까지 이어지는 단계형 UI를 구현하고, 실제 등록·AI 분석·가격 추천 API 확정 전까지는 FE mock adapter로 등록 성공/실패 흐름을 확인 가능하게 만든다.

## 작업 내용

- 기존 `domains/product` 구조와 `DefaultLayout`, 상품 목록/상세 화면의 스타일을 기준으로 등록 화면을 추가한다.
- 화면 흐름은 `사진 등록 -> 기본 정보 -> 사이즈/소재 -> 상태/하자 및 AI 품질 검증 -> 가격 -> 검토 -> 완료` 순서로 구성한다.
- `/products/new`는 인증 필요 라우트로 유지하고, 등록 완료 후 `계속 등록` 또는 `상품 보기` 이동을 제공한다.
- API 요청/응답 필드는 확정하지 않고 `ProductRegistrationDraft`, `ProductRegistrationViewModel` 같은 FE view model과 mock adapter로 분리한다.
- 실제 이미지 업로드/상품 등록 API, AI 품질 분석 트리거, AI 가격 추천 계약은 미확정 항목으로 남기고 필요 시 BE 요청 문서를 별도 작성한다.

## 미결정 사항

- 상품 등록 API endpoint, multipart 업로드 방식, 이미지 업로드와 상품 생성의 분리 여부가 미확정이다.
- AI 품질 검증 API와 가격 추천 API 계약이 미확정이다.
- 상품 사진의 최대 용량 기준이 문서에 없다. 기존 이미지 업로드 화면 기준이 있으면 맞추고, 없으면 FE 임시 검증값으로 표시한다.
- `PROD-001` 필드들의 필수 여부가 다수 `확인 필요`로 남아 있다. MVP 화면에서는 앞면/뒷면 사진, 대표 이미지, 상품명, 브랜드, 색상, 카테고리, 사이즈, 실측, 상태, 하자 여부, AI 품질 검증 사진별 확인, 판매 방식, 판매가 또는 시작가를 우선 필수로 두고 나머지는 선택값으로 제안한다.
- 경매 예정 상품 등록 시 선택 가능한 경매 라이브 후보 조회 방식이 확인 필요하다.
- 임시저장 API가 없으므로 이번 단계에서는 FE 세션 내 draft 유지 또는 비활성/안내 처리 중 하나를 선택해야 한다.

# S15P11A108-240 기본 정보 입력 화면 및 검증 구현 계획

## 배경/목표

기존 S15P11A108-234 온보딩 공통 레이아웃에 ONBOARD-001 기본 정보 입력 폼을 구현한다.
화면 입력과 프론트 검증까지만 담당하고, 저장 API와 다음 단계 이동은 S15P11A108-241에서 구현한다.

## 확인한 기준

- 화면 구성은 `FE/docs/notion/화면 기반 개발 요구 문서.md`의 ONBOARD-001을 우선 적용한다.
- 입력 항목은 닉네임, 성별, 전화번호, 주소, 상세 주소다.
- 닉네임은 특수문자를 제외한 2~10자로 검증한다.
- 성별 선택지는 남성과 여성이다.
- 전화번호는 국내 전화번호 형식으로 검증한다.
- 닉네임, 성별, 전화번호, 주소, 상세 주소를 모두 필수로 처리한다.
- 주소 검색은 Kakao 우편번호 서비스의 공식 스크립트를 사용한다.
- API 저장과 라우트 이동은 이번 작업에 포함하지 않는다.

## 작업 내용

- 라벨, 도움말, 오류 메시지를 묶는 `BaseField` 공통 컴포넌트를 만든다.
- 실제 텍스트 입력과 오류·포커스 상태를 담당하는 `BaseInput` 공통 컴포넌트를 만든다.
- 기본 정보 화면의 폼 값과 오류 상태는 화면 내부 `reactive` 상태로 관리한다.
- 입력창에서 벗어날 때 해당 필드만 검증하고 다음 단계 버튼을 누를 때 전체 필드를 다시 검증한다.
- 오류 입력에는 테두리 색상, 오류 문구, `aria-invalid`, `aria-describedby`를 함께 적용한다.
- 주소와 상세 주소 UI를 분리하고 주소 영역에 검색 버튼을 배치한다.
- Kakao 우편번호 공식 스크립트를 한 번만 불러오는 서비스 함수를 만든다.
- 주소 검색 결과에서 선택한 도로명 또는 지번 주소를 주소 입력값에 반영하고 상세 주소 입력창으로 포커스를 이동한다.
- 주소 검색 스크립트 로딩 중에는 중복 클릭을 막고, 로딩 실패 시 사용자가 직접 주소를 입력하거나 다시 시도할 수 있도록 오류를 표시한다.
- 1440px desktop first로 구성하고 기존 레이아웃 범위 안에서 작은 화면의 기본 줄바꿈만 보호한다.

## S15P11A108-241과의 경계

- HTTP 요청, Axios API 모듈, 인증 토큰, 서버 오류 매핑을 추가하지 않는다.
- 유효한 입력 뒤 실제 저장과 ONBOARD-002 이동은 구현하지 않는다.
- Swagger 계약이 제공되면 요청 필드명과 서버 검증 규칙을 Swagger 기준으로 맞춘다.

## 확정한 미결정 사항

- 닉네임, 성별, 전화번호, 주소, 상세 주소는 모두 필수로 처리한다.
- 주소는 직접 입력할 수 있으며, 주소 검색 버튼으로 Kakao 우편번호 검색도 사용할 수 있게 한다.
- Kakao 공식 가이드의 `https://t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`를 사용한다.
- Kakao 우편번호 서비스는 API 키가 필요 없고 별도 npm 패키지를 설치하지 않는다.

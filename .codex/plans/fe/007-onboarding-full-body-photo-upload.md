# S15P11A108-253 전신 사진 업로드·미리보기·삭제 구현 계획

## 배경/목표

S15P11A108-252에서 만든 ONBOARD-003 전신 사진 영역에 실제 이미지 선택, 모바일 촬영,
미리보기, 변경과 삭제 동작을 연결한다.

이번 작업은 브라우저가 관리하는 임시 사진 상태까지 구현한다. 서버 업로드 API와 파일
용량·해상도·개인정보 동의 정책은 아직 확정되지 않았으므로 서버 저장 계약을 임의로
만들지 않는다.

## 확인한 기준

- `FE/docs/notion/화면 기반 개발 요구 문서.md`는 ONBOARD-003에 사진 등록, 즉시 촬영,
  업로드/촬영 오류 상태를 요구한다.
- 같은 문서의 공통 이미지 업로더 정의는 파일 선택·미리보기·삭제와 업로드 중·실패·완료
  상태를 요구한다.
- `FE/docs/notion/기능 정의서.md`는 AI 시착용 전신 사진을 등록·변경·삭제할 수 있어야
  한다고 정의한다.
- 현재 BE API 문서에는 전신 사진 저장 endpoint와 multipart 요청 계약이 없다.
- 현재 `OnboardingTryOnView.vue`는 252 화면 구조와 스타일을 모두 포함해 파일이 크므로
  사진 파일 처리까지 같은 파일에 넣지 않고 온보딩 전용 컴포넌트로 분리한다.
- 새 라이브러리는 설치하지 않고 브라우저 기본 `File`, `URL.createObjectURL`,
  `URL.revokeObjectURL` API를 사용한다.

## 생성·수정할 파일

### 새 파일: `FE/src/domains/onboard/components/FullBodyPhotoUploader.vue`

다음 역할만 담당하는 전신 사진 전용 컴포넌트를 만든다.

- 숨겨진 일반 이미지 파일 입력
- 모바일 카메라 촬영을 요청하는 파일 입력
- 이미지 파일 여부 확인
- 선택된 사진 미리보기
- 사진 변경과 삭제
- 오류 메시지 표시
- 미리보기 Object URL 생성과 메모리 해제

### 수정: `FE/src/domains/onboard/pages/OnboardingTryOnView.vue`

- `selectedFullBodyPhoto: File | null` 상태를 추가한다.
- 기존 정적 사진 등록 영역을 `FullBodyPhotoUploader`로 교체한다.
- `v-model`로 선택된 사진을 부모 화면과 업로더 컴포넌트 사이에 연결한다.
- 선택된 사진이 있으면 상태 배지를 `등록 완료`, 없으면 `등록 전`으로 표시한다.
- 기존 사진 촬영 가이드와 신체 정보 UI는 유지한다.

## 사진 데이터 흐름

```text
사용자가 사진 등록/즉시 촬영 클릭
  → 숨겨진 file input 열림
  → 사용자가 이미지 선택 또는 촬영
  → FullBodyPhotoUploader가 파일 확인
  → update:modelValue 이벤트 발생
  → OnboardingTryOnView의 selectedFullBodyPhoto 갱신
  → Object URL 생성
  → 화면에 이미지 미리보기와 등록 완료 상태 표시
```

삭제 시에는 반대로 부모 상태를 `null`로 바꾸고 미리보기 URL과 파일 입력값을 초기화한다.

## 컴포넌트 인터페이스

```ts
interface Props {
  modelValue: File | null
}

const emit = defineEmits<{
  'update:modelValue': [file: File | null]
}>()
```

- 부모는 `v-model`을 사용해 선택 파일을 소유한다.
- 자식 컴포넌트는 props를 직접 바꾸지 않고 이벤트로 새 파일 또는 `null`을 전달한다.
- 이 구조를 사용하면 S15P11A108-254에서 저장 API가 확정될 때 부모가 가진 `File`을
  그대로 요청 데이터에 사용할 수 있다.

## 파일 선택과 촬영

### 사진 등록

- `사진 등록` 버튼을 누르면 `accept="image/*"`인 단일 파일 입력을 연다.
- 선택된 파일의 MIME type이 `image/`로 시작하는지 확인한다.
- 이미지가 아니면 부모 상태와 기존 미리보기를 변경하지 않고 오류를 표시한다.
- 파일 형식 whitelist, 최대 용량과 최소 해상도는 정책 미확정이므로 임의 제한하지 않는다.

### 즉시 촬영

- `즉시 촬영` 버튼은 `accept="image/*"`, `capture="environment"`인 입력을 연다.
- 카메라를 지원하는 모바일 브라우저에서는 후면 카메라 촬영 화면을 요청한다.
- 데스크톱이나 미지원 브라우저에서는 일반 이미지 선택창으로 대체될 수 있다.
- 사용자가 취소하면 기존 사진 상태를 유지하고 오류로 취급하지 않는다.
- 별도의 `MediaDevices` 카메라 화면과 권한 모달은 이번 범위에서 구현하지 않는다.

## 미리보기·변경·삭제

- `URL.createObjectURL(file)`로 로컬 미리보기 URL을 만든다.
- `img`에는 선택한 전신 사진이라는 의미가 전달되는 `alt`를 제공한다.
- `object-fit: contain`을 사용해 사진이 영역에서 잘리지 않게 한다.
- 사진 파일명과 `등록 완료` 상태를 텍스트로 함께 표시한다.
- `사진 변경`은 일반 파일 선택창을 다시 연다.
- `사진 삭제`는 아직 서버에 저장되지 않은 임시 파일이므로 즉시 빈 상태로 돌아간다.
- 삭제 후 같은 파일을 다시 선택할 수 있도록 `<input>`의 실제 value도 비운다.

## Object URL 메모리 관리

Object URL은 브라우저 메모리를 사용하므로 다음 시점마다 이전 URL을 해제한다.

- 새 사진으로 교체하기 전
- 사진을 삭제할 때
- ONBOARD-003 화면을 떠나 컴포넌트가 제거될 때

`URL.revokeObjectURL()`을 호출하지 않으면 사진을 여러 번 변경할수록 사용하지 않는
미리보기 데이터가 메모리에 남을 수 있다.

## 오류·접근성

- 이미지가 아닌 파일이면 `이미지 파일만 등록할 수 있습니다.`를 `role="alert"`로 표시한다.
- 파일 선택 취소는 오류로 표시하지 않는다.
- 등록 전 안내는 `role="status"`로 제공한다.
- 미리보기 이미지에는 의미 있는 `alt`를 제공한다.
- 사진 변경과 삭제는 실제 `<button>`으로 제공한다.
- 숨겨진 file input은 화면에서 보이지 않지만 버튼을 통해 키보드로 실행할 수 있다.
- 오류가 발생해도 기존에 선택된 정상 사진은 유지한다.

## 검증 시나리오

1. 사진 등록을 누르면 단일 이미지 파일 선택창이 열린다.
2. 이미지를 선택하면 등록 완료 배지, 파일명과 전신이 잘리지 않는 미리보기가 표시된다.
3. 사진 변경으로 다른 이미지를 선택하면 이전 미리보기가 해제되고 새 사진이 보인다.
4. 같은 파일을 다시 선택해도 정상적으로 변경 처리가 발생한다.
5. 사진 삭제 후 등록 전 상태로 돌아가고 같은 파일을 다시 등록할 수 있다.
6. 이미지가 아닌 파일이면 기존 사진을 유지하고 오류를 표시한다.
7. 파일 선택 또는 촬영을 취소하면 기존 사진과 오류 상태를 변경하지 않는다.
8. 모바일의 즉시 촬영 버튼은 카메라 촬영용 파일 입력을 요청한다.
9. 화면을 이탈하면 생성한 Object URL이 해제된다.
10. 사진을 선택하거나 삭제해도 신체 정보 영역과 이전 단계 동작에는 영향이 없다.
11. 1440px, 820px, 560px 이하에서 미리보기와 액션이 겹치거나 가로로 넘치지 않는다.

보관한 `File` 상태를 서버 요청으로 연결한다.

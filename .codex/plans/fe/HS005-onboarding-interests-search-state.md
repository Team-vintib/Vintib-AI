# S15P11A108-245 관심 정보 검색·선택 및 상태 관리 구현 계획

## 배경/목표

S15P11A108-244에서 구현한 ONBOARD-002 관심 브랜드·카테고리 선택 화면에 브랜드 검색을
추가한다. 검색 결과가 바뀌어도 이미 선택한 브랜드와 카테고리 상태가 유지되어야 하며,
검색 결과가 없을 때는 빈 상태를 표시한다.

이번 작업은 프론트 화면 내부의 검색·선택 상태까지만 담당한다. 관심 정보 저장 API,
건너뛰기, 다음 단계 이동은 S15P11A108-250의 범위로 남긴다.

## 확인한 기준

- `FE/docs/notion/화면 기반 개발 요구 문서.md`의 ONBOARD-002에는 입력 필드가
  `브랜드 검색` 1개로 정의되어 있다.
- Jira 설명의 “브랜드·카테고리 목록”은 관심 정보 전체 영역을 가리키는 것으로 해석하고,
  검색 필터는 문서에 명시된 브랜드 목록에만 적용한다.
- 브랜드와 카테고리는 선택 입력이며 선택 개수 제한은 두지 않는다.
- 실제 브랜드 조회 API가 아직 확정되지 않았으므로 기존 `브랜드 A`부터 `브랜드 F`까지의
  화면 상수를 필터링한다.
- 검색어는 화면 내부에서만 사용하는 상태이므로 Pinia가 아닌 컴포넌트 `ref`로 관리한다.
- 새 라이브러리는 설치하지 않는다.

## 작업 내용

- `OnboardingInterestsView.vue`에 라벨이 있는 브랜드 검색 입력창을 추가한다.
- 기존 `BaseField`와 `BaseInput`을 재사용해 입력 의미, 포커스 스타일과 도움말을
  기존 폼 규칙에 맞춘다.
- 검색어 앞뒤 공백을 제거하고 대소문자를 구분하지 않은 부분 일치 방식으로 브랜드를
  필터링한다.
- 원본 브랜드 배열은 변경하지 않고 `computed`로 화면에 표시할 브랜드 목록만 계산한다.
- 검색어 상태와 `selectedBrandIds`를 분리해 검색 결과에서 항목이 사라져도 선택 상태를
  변경하지 않는다.
- 검색어를 지우거나 다른 검색어로 다시 항목이 표시되면 기존 선택 스타일과
  `aria-pressed` 상태를 복원한다.
- 검색 결과가 0개면 브랜드 선택 영역 안에 `검색 결과가 없습니다.` 빈 상태를 표시한다.
- 빈 상태는 보조 텍스트 색상과 경계선으로 표현하고, 스크린 리더가 결과 변화를 인지할 수
  있도록 상태 영역에 적절한 접근성 속성을 적용한다.
- 기존 브랜드·카테고리 선택/해제, 선택 개수, 이전 단계 이동과 반응형 레이아웃은 유지한다.
- 구현 상태 문서와 화면 목록에서 ONBOARD-002를 `검색·선택 완료, 저장 대기` 상태로
  갱신한다.

## 검증 시나리오

1. 검색어가 없으면 브랜드 A~F가 모두 표시된다.
2. `브랜드 A`, `A`, 앞뒤 공백이 포함된 검색어로 브랜드 A가 표시된다.
3. 존재하지 않는 검색어를 입력하면 결과 없음 상태가 표시된다.
4. 브랜드 A를 선택한 뒤 다른 검색어를 입력해 숨겼다가 검색어를 지우면 선택 상태가
   유지된다.
5. 필터된 결과에서 브랜드를 선택·해제해도 전체 선택 개수가 정확하다.
6. 브랜드 검색 중에도 카테고리 선택 상태와 선택 개수가 유지된다.
7. 검색 입력, 브랜드 버튼과 카테고리 체크박스를 키보드로 조작할 수 있다.

## S15P11A108-250과의 경계

- 관심 정보 저장 API와 요청 타입을 추가하지 않는다.
- 저장 로딩·성공·실패 상태를 추가하지 않는다.
- 건너뛰기 버튼과 스킵 요청을 구현하지 않는다.
- 다음 단계 버튼의 저장 및 ONBOARD-003 이동을 구현하지 않는다.

## 미확정 사항 처리

- 실제 브랜드 API와 브랜드 데이터 구조가 확정되면 화면 상수를 API 응답으로 교체한다.
- 선택 개수 제한과 서버 검증 오류는 API 계약이 확정되는 S15P11A108-250에서 처리한다.

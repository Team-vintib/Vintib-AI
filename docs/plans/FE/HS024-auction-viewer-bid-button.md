# HS024 — AUCT-003~006 시청자 입찰 버튼 반응

- Jira: S15P11A108-432 (`[AUCT-003~006 | FE] 시청자 버튼 반응 구현`) / 에픽 S15P11A108-209 [AUCT]
- 브랜치: `feat/209-chat-auction-panel` (에픽 209 재사용, HS023 낙찰 축하 커밋 위에 이어서)

## 배경 / 목표

라이브 경매 패널의 시청자 입찰 버튼 반응을 구현한다.
- AUCT-003 증액 버튼 입찰(모두에게 동일한 "다음 입찰가" 버튼)
- AUCT-004 중복 클릭 방지(같은 단계에서 여러 번 눌러도 1단계만)
- AUCT-005 서버 기준 선착순(같은 버튼 여러 명 → 서버에 먼저 도착만 성공) — **서버 판정 필수**
- AUCT-006 연속 입찰 제한(최근 성공자는 다른 사람이 입찰하기 전까지 재입찰 불가)
- AUCT-011 최고 입찰자 닉네임(전체) + 현재가 표시

사용자 요구(기억): **입찰 후 버튼이 잠깐(약 3초) 홀드됐다가, 다른 사람이 입찰하면 다시 입찰 가능**해지고, **현재 (먼저 누른) 최고 입찰자 ID가 화면에 뜬다.** 서버 선착순 판정은 BE 몫이라, FE는 **버튼 UX + mock 경쟁 사이클**로 구현하고 실제 판정은 `docs/requests/BE/009`(입찰/선착순/STOMP) 참조.

## 현황

- `LiveAuctionPanel`: 증액 버튼(`nextBid`), `placeMockBid`(BIDDABLE→PENDING 480ms→LEADING), 최고 입찰자 표시, 중복 클릭 방지(가드), 남은 시간 카운트다운 — mock 이미 존재.
- 부족: 입찰 후 **3초 홀드 → mock 경쟁자 재입찰 → 재입찰 가능** 사이클 없음(LEADING에서 멈춤). 최고 입찰자 ID 강조 약함.
- BE: 입찰/시작/종료/선착순/STOMP 전부 없음 → **009에 이미 요청됨**.

## 작업 내용 (구두)

1. **입찰 사이클 mock 확장**: BIDDABLE →(클릭) PENDING(서버 접수 흉내) → LEADING(내가 최고, "나" 표시) → **약 3초 홀드** → mock 경쟁자가 더 높게 입찰(현재가 상승·최고 입찰자 ID 변경) → BIDDABLE(재입찰 가능). AUCT-006(연속 입찰 제한)·AUCT-008(보류 해제 후 재입찰) 흐름을 mock으로 표현. **정해진 경매 시간(카운트다운) 동안 이 사이클을 반복**한다.
2. **입찰 확인 즉시 최고 입찰자 반영**: 입찰이 확정(mock 접수)되는 즉시 현재가·최고 입찰자 ID를 갱신한다.
3. **종료 직전 자동 연장(AUCT-010)**: 종료 임박에 유효 입찰이 발생하면 종료 시각을 연장한다. **기능 정의서대로 종료 3초 이하에 입찰 → +5초**. 반복 발생 시 계속 연장. (실제 연장 판정은 BE 정책 기준.)
4. **중복 클릭 방지 유지/강화**(AUCT-004): PENDING/LEADING/홀드 중 버튼 비활성 + 가드.
5. **최고 입찰자 ID 표시 강조**(AUCT-011): 현재 최고 입찰자 닉네임(전체) + 현재가를 눈에 띄게.
6. **BE 판정은 요청 참조**: 서버 선착순(AUCT-005)·실제 입찰/보류/연장은 `docs/requests/BE/009`에 있음 → FE 코드에 `BE 확인 필요`(선착순·연장 판정은 서버) 주석. 부족한 게 있으면 009 보강.

## 확인 필요 (미결정)

- "3초 홀드"는 FE 연출값(서버 정책과 별개) — 실제 연속입찰 제한 해제 시점은 BE 이벤트 기준으로 대체.
- mock 경쟁자 자동 입찰은 데모용. 실제는 STOMP `BID_PLACED`로 대체.

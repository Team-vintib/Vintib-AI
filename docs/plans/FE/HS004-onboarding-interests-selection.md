# S15P11A108-244 관심 브랜드·카테고리 선택 화면 구현 계획

## 배경/목표

기존 ONBOARD-002 임시 화면을 실제 관심 브랜드·카테고리 선택 화면으로 교체한다.
이번 작업은 화면 UI와 프론트 선택 상태 관리까지만 담당하고, 검색 기능은 S15P11A108-245,
저장 API·건너뛰기·다음 단계 이동은 S15P11A108-250에서 구현한다.

## 확인한 기준

- 화면 구성과 동작은 `FE/docs/notion/화면 기반 개발 요구 문서.md`의 ONBOARD-002를 우선 적용한다.
- 관심 브랜드와 카테고리는 모두 선택 입력이며 다중 선택할 수 있다.
- 브랜드 후보는 문서에 명시된 `브랜드 A`부터 `브랜드 F`까지 사용한다.
- 카테고리 후보는 아우터, 상의, 하의, 원피스, 신발, 액세서리를 사용한다.
- 선택 가능 개수는 미확정이므로 프론트에서 임의 제한하지 않는다.
- 선택 상태는 Forest Green 계열의 soft 배경과 텍스트·체크 표시를 함께 사용한다.
- 1440px desktop first를 기준으로 하되 작은 화면에서 목록이 자연스럽게 줄바꿈되도록 한다.
- 새 라이브러리는 설치하지 않는다.

## 작업 내용

- `OnboardingInterestsPlaceholderView.vue`를 실제 화면 역할의
  `OnboardingInterestsView.vue`로 교체하고 라우터의 컴포넌트 참조를 갱신한다.
- 화면 안내 문구를 `관심 있는 브랜드와 카테고리를 선택해 주세요.`로 변경한다.
- 브랜드 선택 영역에 `브랜드 A`부터 `브랜드 F`까지 선택 가능한 칩 버튼을 배치한다.
- 브랜드 버튼은 `aria-pressed`를 사용하고 선택 상태를 텍스트와 체크 표시로 함께 전달한다.
- 카테고리 선택 영역에 아우터, 상의, 하의, 원피스, 신발, 액세서리 선택지를 배치한다.
- 카테고리는 실제 checkbox와 label을 연결해 마우스와 키보드로 조작할 수 있게 한다.
- 선택된 브랜드 ID와 카테고리 ID는 화면 내부의 반응형 배열로 관리한다.
- 같은 항목을 다시 선택하면 선택이 해제되도록 토글한다.
- 선택한 개수를 각 영역에 표시해 색상에만 의존하지 않고 현재 상태를 확인할 수 있게 한다.
- 기존 이전 단계 동작은 유지한다.
- 다음 단계 버튼은 S15P11A108-250에서 실제 저장·이동을 연결하기 전까지 비활성 상태로 둔다.
- 구현 상태 문서와 화면 목록에서 ONBOARD-002를 `선택 UI 완료, 검색·저장 대기` 상태로 갱신한다.

## S15P11A108-245와의 경계

- 브랜드 검색 입력창과 검색어 상태를 추가하지 않는다.
- 검색 결과 필터링과 검색 결과 없음 상태를 구현하지 않는다.
- 검색 도중 선택 상태 유지 동작은 구현하지 않는다.

## S15P11A108-250과의 경계

- 관심 정보 저장 API와 요청 타입을 추가하지 않는다.
- 저장 로딩·실패 상태를 추가하지 않는다.
- 건너뛰기 버튼과 스킵 요청을 구현하지 않는다.
- 다음 단계 버튼의 저장 및 ONBOARD-003 이동을 구현하지 않는다.

## 미확정 사항 처리

- 선택 개수 제한은 미확정이므로 제한 없이 선택할 수 있게 한다.
- 서버가 선택 제한 오류를 반환하는 경우의 처리는 S15P11A108-250에서 API 계약에 맞춘다.
- 실제 브랜드 데이터 API가 확정되지 않았으므로 이번 작업에서는 요구 문서의 브랜드 A~F를 화면 상수로 사용한다.

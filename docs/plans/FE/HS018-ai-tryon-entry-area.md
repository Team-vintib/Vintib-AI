# TRYON-003 AI 시착 진입 영역

## 배경/목표

`S15P11A108-425`에서 `LIVE-005` 라이브 시청 화면의 AI 시착 버튼을 실제 패널 UI와
연결한다. 기존 Figma의 전신 사진·라이브 연결 상품·선택 상품 카드 구성을 단순화해,
사용자의 전신 사진 한 장을 중심으로 등록 전·준비·생성 중·완료·실패 상태를 mock으로
표현한다. 실제 사진 저장, AI 생성과 결과 저장 API는 연결하지 않는다.

## 기준 자료

- Jira `S15P11A108-425 [TRYON-003] [FE] AI 시착 진입 영역 구현`
- Figma Make 프로토타입의 라이브 시청·AI 시착 패널·생성 중·결과 화면
- 사용자가 확정한 변경 구성
- `FE/docs/notion/화면 기반 개발 요구 문서.md`
- `FE/docs/notion/기능 정의서.md`
- `FE/docs/notion/프론트엔드 디자인 구현 규칙.md`
- `FE/docs/frontend/screens/LIVE-005/requirements.md`
- `.codex/requests/be/003-onboarding-tryon-profile-api.md`
- `.codex/requests/be/012-live-watch-detail-contract-gaps.md`
- `.claude/requests/ai/001-tryon-result-contract.md`

기능 정의서는 라이브 중 시착을 `TRYON-004`로 분류하지만 Jira 425는 `TRYON-003`을
사용한다. 이번 브랜치와 커밋은 Jira 425를 기준으로 하고, 화면 문서에는 라이브
`TRYON-003/004` 연관성을 함께 기록한다.

## 확정 화면 구성

### 패널 진입과 유지

- 영상 우측 하단의 `AI 시착` 버튼으로 영상 영역 오른쪽에 약 530px 패널을 연다.
- 패널이 열려도 영상, 채팅, 반응과 경매 상태는 다시 생성하지 않고 그대로 유지한다.
- 패널 상단에 닫기 버튼을 제공한다.
- 패널을 닫았다 다시 열면 진행 중인 mock 생성이나 현재 결과를 유지한다.
- 선택 상품이 바뀌면 이전 생성 결과와 오류를 초기화하고 새 상품의 준비 상태로 돌아간다.

### 공통 헤더

- 제목은 `AI 시착`으로 표시한다.
- 상품 카드를 반복하지 않고 `시착 상품 · {선택 상품명}` 한 줄만 표시한다.
- 선택 상품이 없거나 라이브가 예정·종료 상태이면 진입 버튼을 비활성화한다.

### 등록 이미지가 있는 상태

- 등록된 전신 사진 한 장을 기존보다 크게 표시한다.
- 하단에 보조 버튼 `이미지 변경`과 Violet 주요 버튼 `AI 시착 시작`을 나란히 둔다.
- `이미지 변경`은 파일 선택 창을 열고, 이미지 파일이면 패널의 미리보기를 즉시 교체한다.
- 이번 스토리에서는 변경 사진을 로컬 mock 상태에만 반영한다. 계정 등록 사진의 영구 변경
  여부와 저장 API는 확정된 것처럼 처리하지 않는다.

### 등록 이미지가 없는 상태

- 큰 빈 이미지 영역과 `AI 시착에 사용할 이미지를 등록해 주세요` 안내를 표시한다.
- `이미지 등록` 버튼으로 파일을 선택할 수 있다.
- 사진이 선택되기 전 `AI 시착 시작` 버튼은 비활성화한다.
- 이미지가 아닌 파일은 `이미지 파일만 등록할 수 있습니다` 오류를 표시한다.
- 용량·해상도 제한은 계약 미확정이므로 임의의 숫자로 제한하지 않고 오류 영역만 준비한다.

### 생성 중

- 사용자가 시작 버튼을 눌렀을 때의 전신 사진을 크게 유지한다.
- 사진 위에 로딩 표시와 `AI 시착 이미지를 생성하고 있습니다` 안내를 표시한다.
- 생성 중에는 이미지 변경과 중복 시작을 막는다.
- 가짜 진행률 숫자는 표시하지 않는다.

### 생성 완료

- Figma의 결과 이미지 중심 구성과 사이즈·핏 안내 문구를 유지한다.
- 선택 상품명은 패널 헤더에서만 표시하고 결과 영역에서는 반복하지 않는다.
- `다시 시착하기`, `결과 저장` 버튼을 제공한다.
- `다시 시착하기`는 즉시 재생성하지 않고 큰 등록 이미지와 이미지 변경·시작 버튼이
  있는 준비 상태로 돌아간다.
- 결과 저장은 로컬 완료 피드백까지만 제공하고 실제 저장 API는 연결하지 않는다.

### 생성 실패

- 결과 영역에 실패 안내와 `다시 시도` 버튼을 표시한다.
- 다시 시도하면 현재 전신 사진과 선택 상품으로 생성 중 상태를 다시 시작한다.
- mock query/state로 성공과 실패를 재현할 수 있게 한다.

## 상태 및 컴포넌트 경계

- `domains/tryon/types`에 라이브 시착 패널 상태 타입을 둔다.
  - `EMPTY`, `READY`, `GENERATING`, `RESULT`, `ERROR`
- `domains/tryon/constants`에 등록 사진, 결과, 사이즈·핏 안내 mock을 둔다.
- `domains/tryon/components/LiveTryOnPanel.vue`에 사진 선택, 상태별 패널과 로컬 전환을 둔다.
- `LiveVideoStage.vue`는 AI 시착 진입 event와 비활성 상태만 제공한다.
- `LiveWatchPage.vue`가 패널 열림 상태, 선택 상품과 TRYON 컴포넌트를 조립한다.
- 패널은 `v-show` 또는 동일한 유지 방식으로 닫을 때 내부 생성 상태를 소멸시키지 않는다.
- 새 라이브러리는 설치하지 않는다.

## mock 확인 경로

- `/lives/101`: 등록 사진이 있는 기본 준비 상태
- `/lives/101?tryon=empty`: 등록 사진 없음
- `/lives/101?tryon=error`: mock 생성 실패
- `/lives/101?mock=empty-products`: 선택 상품 없음, AI 진입 비활성
- `/lives/101?mock=scheduled`, `/lives/101?mock=ended`: AI 진입 비활성

query는 UI 확인용 mock 전용이며 실제 API 계약으로 사용하지 않는다.

## API 비교 및 요청 문서

`012`는 변경된 AI 시착 영역을 명시적으로 제외한다. 현재 확인한 계약에는 결과
조회·삭제는 있으나 현재 전신 사진 조회, 사진 변경, 시착 생성과 임시 결과 저장 분리가
없으므로 구현 승인 후 `.codex/requests/be/013-live-tryon-contract.md`를 작성한다.

요청 문서에서 다음을 확인한다.

- 현재 회원의 등록 전신 사진 URL 또는 미등록 상태 조회
- 라이브 패널에서 선택한 전신 사진을 영구 변경할지 현재 시착에만 사용할지
- 이미지 형식·용량·해상도와 개인정보 보관 정책
- 선택 상품의 AI 시착 지원 여부
- 생성 요청에 필요한 `productId`, 사진 식별자 또는 multipart 전달 방식
- 동기 응답 또는 비동기 job·상태 조회 방식
- 생성 실패 코드와 재시도 정책
- 생성 결과와 사용자가 누르는 `결과 저장`의 분리

# S15P11A108-252 전신 사진·신체 정보 등록 화면 구현 계획

## 배경/목표

ONBOARD-002 다음 단계에 연결된 ONBOARD-003 임시 화면을 전신 사진과 신체 정보를
등록하는 실제 화면 구조로 교체한다.

이번 작업은 화면 골격과 정적 UI를 완성하는 범위다. 사진 파일 선택·미리보기·삭제는
S15P11A108-253에서, 신체 정보 입력 상태·검증·저장·건너뛰기는 S15P11A108-254에서
구현한다.

## 확인한 기준

- `FE/docs/notion/화면 기반 개발 요구 문서.md`는 ONBOARD-003에 전신 사진 등록/즉시 촬영,
  키·몸무게·가슴·허리·엉덩이 입력, 촬영 조건 안내, 건너뛰기와 다음 단계를 요구한다.
- 같은 문서에서 사진 업로드 실패, 카메라 권한 실패, 치수 형식 오류를 예외 상태로
  정의하지만, 각 오류를 발생시키는 실제 동작은 후속 이슈 범위다.
- `FE/docs/notion/기능 정의서.md`는 사진과 모든 신체 정보를 선택 입력으로 정의하며,
  전신 사진이 없으면 AI 가상 시착을 이용할 수 없다고 명시한다.
- 현재 `/onboarding/try-on` 라우트와 `OnboardingTryOnView.vue` 임시 화면이 존재하므로
  라우트나 페이지 파일을 새로 만들지 않고 기존 화면을 교체한다.
- 기존 `OnboardingLayout`, `BaseField`, `BaseButton`과 전역 디자인 토큰을 우선
  재사용한다.
- 가슴·허리·엉덩이의 단위와 허용 범위는 문서상 `확인 필요`이므로 이번 화면에서
  임의의 단위·범위·검증 규칙을 확정하지 않는다.
- 새 라이브러리와 이미지 에셋은 추가하지 않는다.

## 화면 구조

`OnboardingTryOnView.vue` 안을 다음 두 개의 주요 영역으로 구성한다.

1. **전신 사진 영역**
   - 영역 제목과 `선택 사항` 배지
   - 등록 전 상태를 나타내는 업로드 플레이스홀더
   - `사진 등록`, `즉시 촬영` 액션
   - 전신 노출, 정면 자세, 몸의 형태가 보이는 옷에 대한 촬영 안내
   - 전신 사진 미등록 시 AI 시착을 이용할 수 없다는 정보 문구
2. **신체 정보 영역**
   - 영역 제목과 선택 입력 안내
   - 키(cm), 몸무게(kg), 가슴, 허리, 엉덩이 필드 자리
   - 데스크톱에서는 읽기 쉬운 그리드, 작은 화면에서는 1열 배치
   - 실제 치수 입력이 시착 정확도 향상에 사용된다는 안내

페이지 하단 액션은 기존 온보딩 레이아웃을 사용해 `이전 단계`, `건너뛰기`,
`다음 단계`를 노출한다.

## 작업 내용

### ONBOARD-003 화면

- `FE/src/domains/onboard/pages/OnboardingTryOnView.vue`의 임시 안내 화면을 실제 등록
  화면 구조로 교체한다.
- 영역 제목은 heading 계층을 지키고, 촬영 안내는 목록 마크업으로 제공한다.
- 사진 액션은 실제 파일/카메라 동작과 혼동되지 않도록 후속 기능 연결 전까지
  비활성 상태와 보조 설명을 제공한다.
- 신체 정보 필드는 252에서 배치와 라벨·단위 표현만 담당한다. 후속 254에서 값 상태와
  검증을 연결할 수 있도록 필드 이름과 DOM 구조를 명확히 유지한다.
- `이전 단계`는 기존대로 ONBOARD-002로 이동한다.
- `건너뛰기`, `다음 단계`의 저장 및 이동은 254 범위이므로 252에서는 비활성 상태로
  노출하고 후속 작업 예정임을 보조 문구로 전달한다.
- 데스크톱, 태블릿, 모바일 폭에서 콘텐츠가 겹치거나 가로로 넘치지 않도록 반응형
  레이아웃을 추가한다.

### 입력 UI

- 숫자 입력의 실제 값 상태와 검증은 254 범위이므로 252에서는 필드 구조와 시각 표현만
  구현한다.
- 단위 표시는 placeholder에만 의존하지 않고 라벨 또는 입력 주변의 별도 텍스트로
  제공한다.
- 기존 `BaseInput.vue`를 변경하지 않고 화면 전용 입력 마크업으로 구성해 ONBOARD-001·002
  사용처에 회귀 위험을 만들지 않는다.

### 상태 문서

- `FE/docs/frontend/implementation/status.md`의 ONBOARD-003 상태를
  `화면 구현, 사진·저장 동작 대기`로 갱신한다.
- `FE/docs/frontend/screens/screen-inventory.md`도 같은 구현 경계가 드러나도록 갱신한다.
- 구조에 새 컴포넌트를 추가하지 않으므로
  `FE/docs/frontend/implementation/current-structure.md`는 변경하지 않는다.

## 검증 시나리오

1. `/onboarding/try-on` 진입 시 온보딩 3단계와 실제 등록 화면이 표시된다.
2. 전신 사진 영역에 등록 전 상태, 사진 등록, 즉시 촬영과 세 가지 촬영 안내가 보인다.
3. 키, 몸무게, 가슴, 허리, 엉덩이 필드의 라벨과 단위 표현을 구분할 수 있다.
4. 사진과 신체 정보가 선택 사항임을 화면에서 명확히 알 수 있다.
5. 사진 액션과 다음 단계 액션은 미구현 기능을 실행하지 않으며 비활성 상태가 전달된다.
6. 이전 단계를 누르면 `/onboarding/interests`로 이동한다.
7. 키보드 탐색 시 활성 요소의 포커스가 보이고, 필드 라벨과 안내가 연결된다.
8. 1440px, 820px, 560px 이하에서 영역과 필드가 겹치거나 가로로 넘치지 않는다.
9. ONBOARD-001·002 화면의 기존 레이아웃과 버튼 동작에는 변화가 없다.

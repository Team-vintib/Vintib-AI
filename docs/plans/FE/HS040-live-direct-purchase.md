## 배경/목표

라이브 시청 화면에서 선택한 상품의 실제 상세 필드를 보여 주고, 정찰제 상품은 경매 패널 대신
즉시구매 흐름을 제공한다. 경매 상품에는 공개 입찰 내역을 보강하고, 상품 큐와 채팅 오류 안내의
표현도 현재 계약과 기획 문구에 맞춘다.

## 작업 내용

- 라이브 상품 응답의 `material`, `measurements`, `defectSummary`를 시청 뷰모델에 연결한다.
  `measurements` 객체는 한 줄 표시 문자열로 변환한다.
- 상품 큐에서 가격이 없는 경매 예정 상품은 `가격 정보 준비 중` 대신 `경매 예정`으로 표시한다.
- 시청자가 `DIRECT_SALE`·`ON_SALE` 상품을 선택하면 경매 패널 대신 정찰제 구매 패널을
  표시하고, 밀어서 구매를 완료하면 기존 구매 확인 창을 연다.
- 라이브 주문 생성에는 선택 상품 ID와 현재 `liveId`를 함께 전송한다. 구매 완료 후 상품 상태와
  포인트 잔액을 갱신하며, 포인트 부족 오류는 기존 구매 확인 창에서 충전 경로와 함께 안내한다.
- 현재 경매의 공개 입찰 내역을 커서 페이지네이션으로 조회하고 더 보기로 이전 내역을 추가한다.
- AI 욕설 판정으로 차단된 채팅 안내만 일반 연결 오류보다 크고 굵게 표시한다.

## 확인 사항

- 정찰제 구매 패널은 `saleType === 'DIRECT_SALE' && saleStatus === 'ON_SALE'`이며 시청자
  화면일 때만 활성화한다. 호스트 본인 상품과 판매 완료 상품에는 구매 동작을 노출하지 않는다.
- 밀기 완료만으로 주문을 확정하지 않고, 기존 구매 확인 창에서 배송지와 포인트를 확인한 뒤
  주문을 생성한다.
- 경매 입찰 내역은 비회원도 조회할 수 있으며 `nextCursor`를 서버 응답 그대로 다음 요청에 쓴다.
- 서버·배포 환경이 필요한 주문 집계, 포인트 차감, 본인 상품 거절은 정적 검사와 로컬 화면 검증
  이후 실제 BE 환경에서 최종 확인한다.

## QA 반영 (구매자 화면 확인 후)

진행 중인 라이브(`/lives/6`)를 시청자로 열어 확인한 세 가지를 고쳤다.

- **상품 큐 강조가 두 개로 보임**: `--selected`와 `--current`가 같은 좌측 액센트 바를 그리고
  있었다. 좌측 바는 시청자가 고른 상품 전용(흰색)으로 두고, 판매자가 소개 중인 상품은 `NOW`
  배지로만 구분한다.
- **정찰제 패널로 전환되지 않음**: 패널 분기가 `saleType === 'DIRECT_SALE'` 하나였고, 판매자가
  상품을 전환해도 시청자 선택이 첫 상품에 머물러 이전 상품 기준으로 남았다. 분기 기준은
  **시청자가 고른 상품**으로 두되, 그 상품의 경매가 걸려 있을 때(`RUNNING`/`READY`)만 경매
  패널을 유지한다. 경매 상품(`AUCTION`/`AUCTION_SCHEDULED`/`AUCTION_IN_PROGRESS`)이 아니면
  정찰제 패널을 띄우고, `saleType`이 비어 있고 가격만 있는 상품도 정찰제로 본다.
  소개 상품 전환은 시청자가 아직 아무 상품도 고르지 않은 동안에만 선택을 따라가게 한다.
- **욕설 차단 안내가 강조되지 않음**: 강조 스타일이 존재하지 않는 토큰(`--font-size-sm`)을
  참조해 선언이 무효였다. 정의된 `--font-size-body`(15px)로 바꾸고, 본문 웹폰트가 700까지만
  실려 있어 weight로는 더 굵어지지 않으므로 획 두께(`-webkit-text-stroke`)를 더했다.
  차단 안내는 다음 메시지를 보내거나 내 메시지가 정상 브로드캐스트되면 사라진다.

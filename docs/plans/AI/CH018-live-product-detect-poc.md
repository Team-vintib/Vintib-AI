# 라이브 상품 자동 감지 PoC (YOLO + VLM)

## 배경/목표

에픽 `S15P11A108-211` 소속. 라이브 방송 중 판매자가 상품을 카메라에 들어 보이는 순간을
YOLO로 감지하고 VLM으로 설명을 뽑아 자동 등록에 활용할 수 있을지 아이디어에서 출발했다.
리서치 결과 두 가지
이유로 실제 기능 구현은 지금 단계에서 불가능하다:

1. **라이브 프레임 접근 경로가 아예 없다.** OpenVidu(WebRTC 미디어 서버)가 아직 설치
   전이고, BE 쪽 결정 자체가 "방송 종료 후 일괄 처리를 기본으로", STT/녹화 파이프라인은
   "당분간 착수하지 않음"이다(`.claude/requests/ai/002-live-webrtc-decision.md`).
2. **`FE/docs/notion/기능 정의서.md`의 "제외 범위"에 "미등록 상품 AI 자동 등록"과
   "이미지 기반 AI 상품 설명 생성"이 명시적으로 들어있다** — 지금 구상과 정확히 겹치는
   MVP 제외 항목이다.

그래서 목표는 라이브/BE 연동 없이, **로컬 웹캠으로 "판매자가 상품을 들어 보이는 순간"을
시뮬레이션해서 YOLO(감지) → VLM(설명) 2단계 파이프라인이 개념적으로 성립하는지만
검증**하는 PoC다. `AI/validation/` 안에서만 진행하고 프로덕션 워커/게이트웨이/BE 어디에도
연결하지 않는다.

## 작업 내용

`AI/validation/LIVE/product-auto-detect/`에 스크립트 하나로 가볍게 구현한다.
`computer_vision` conda 환경(`ultralytics 8.3.155` 이미 설치됨)을 그대로 쓴다. VLM은
`worker/models/quality_vlm/loader.py`(Qwen3-VL, 4bit)를 CatVTON 검증 폴더와 같은 이유로
로컬 복사해서 쓴다 — 프로덕션 모듈에 실시간 의존하지 않기 위함.

`cv2.VideoCapture(0)`로 웹캠에서 일정 주기(0.5초)로 프레임을 가져와 사전학습 YOLO(COCO
가중치)로 객체를 감지한다. COCO 80개 클래스엔 "의류/상품" 범용 클래스가 없어서, 클래스
매칭 대신 "사람 근처에 크게 잡히는 미분류 전경 객체"를 휴리스틱으로 우선 시도한다 — 이게
안정적으로 걸리는지 자체가 이번 PoC의 핵심 검증 대상이다. 후보 bbox가 N프레임(5~10)
연속으로 크기·위치가 일정하면 "들어 보이는 순간"으로 확정한다(오탐 방지).

확정된 프레임에서 후보 영역을 여유 있게 크롭해 VLM에 넣고, `quality_vlm/prompts.py`
스타일을 참고한 프롬프트로 상품 설명을 한 문장 뽑는다. 결과(원본 프레임+bbox 시각화+VLM
캡션)는 콘솔 출력과 이미지 저장으로 남긴다.

실제 검증은 사용자가 직접 웹캠 앞에서 여러 상품(옷/아우터/신발 등)을 들어 보이며
반복 테스트한다 — YOLO 감지 안정성, 크롭 영역 적절성, VLM 설명 정확도를 육안으로 확인.

## 범위 밖

- 라이브 스트림(OpenVidu) 연동, BE 상품 등록 API 호출, 워커/게이트웨이 wiring,
  `FeatureType` 추가.
- YOLO 파인튜닝(빈티지 의류 전용 커스텀 클래스 학습) — 사전학습 가중치로 개념만 검증.
- 다중 상품 동시 인식, 트래킹(ID 유지).

## 확인이 필요한 미결정 사항

- "사람 근처에 크게 잡히는 미분류 전경 객체" 휴리스틱이 실제로 안정적으로 동작하는지는
  테스트 전까지 미지수 — 안 되면 다른 신호(예: 정지 시간, 손 위치)를 추가로 시도해야 할 수
  있음.
- PoC 결론이 긍정적이어도, 다음 단계(라이브 인프라, 상품 이미지 필드, BE 연동, MVP 제외
  범위 재검토)는 이번 작업 범위에 포함하지 않고 별도로 논의한다.

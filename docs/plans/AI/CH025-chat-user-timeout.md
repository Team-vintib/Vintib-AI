# CH025 — 도배/욕설 반복 시 15초 임시 채팅 차단

에픽 `S15P11A108-217`.

## 배경/목표

지금은 스팸/악성 메시지를 건별로만 막는다 — 같은 사람이 계속 도배·욕설을 반복해도 매번 그
메시지 하나씩만 숨기거나 차단할 뿐, 그 사람이 채팅을 계속 시도하는 것 자체는 막지 않는다.
짧은 시간 안에 반복 위반한 사용자는 일정 시간(15초) 채팅 자체를 못 하게 막아서 남용을 억제한다.

## 작업 내용

- AI: 사용자별 위반(스팸/악성으로 차단된 횟수)을 슬라이딩 윈도우로 추적하는 컴포넌트를 추가한다
  (`SpamDetector`가 쓰는 `InMemoryStateStore`와 같은 패턴 재사용). 윈도우 안에서 위반 횟수가
  임계치를 넘으면 `mute_until` 타임스탬프를 기록한다.
- AI: `moderate()` 진입 시 스팸/악성/질문 판정보다 **먼저** "지금 음소거 상태인지"를 확인한다.
  음소거 중이면 나머지 판정을 건너뛰고 즉시 음소거 판정(남은 초 포함)을 반환한다.
- AI: 응답 스키마에 남은 음소거 시간(초) 필드를 추가한다.
- BE: AI가 음소거 판정을 돌려주면 메시지를 저장·브로드캐스트하지 않고, 기존 차단 알림
  채널(`/user/queue/errors`)로 음소거 안내(+남은 초)를 발신자에게만 보낸다 — 차단 알림 기능과
  같은 패턴.
- FE: 음소거 안내를 받으면 입력창을 비활성화하고 남은 시간을 보여주다가, 시간이 지나면 자동으로
  다시 입력 가능하게 되돌린다.

## 확인 필요

- **위반 임계치**: 몇 초 안에 몇 번 차단돼야 음소거할지. 제안: 스팸 판정과 같은 10초 윈도우 안에
  스팸/악성으로 차단된 메시지가 **3회 이상**이면 15초 음소거. (숫자 확정 필요)
- **음소거 범위**: 그 방송(`live_id`)에서만 막을지, 계정 전체(모든 방송)에서 막을지 — 제안:
  방송 단위(지금 스팸 판정이 `live_id` 없이 `user_id`만으로 걸려 있는 것과 별개로, 음소거는
  방송별로 격리하는 게 자연스러워 보임).
- 음소거 상태는 게이트웨이 프로세스 인메모리에만 둔다 — 다중 게이트웨이 확장 시 안 맞는 기존
  한계(`S15P11A108-188`)를 그대로 물려받는다. 지금 스코프에선 감수한다.

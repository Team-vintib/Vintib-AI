# 미낙찰 상품 처리 — 판매방식 전환 엔드포인트 의미 확인

- **요청자 파트**: FE
- **대상 파트**: BE
- **관련 이슈**: FE `S15P11A108-440`(미낙찰 상품 처리), 스토리 `-103`[AUCT-014], 에픽 `-209`[AUCT]
- **관련 기능**: AUCT-014(미낙찰 상품 복원), PROD-005(판매 방식)
- **상태**: FE는 기존 상품 API로 처리를 **연결 완료**. 아래 두 가지 **의미 확인**만 필요.

## 배경

방송 종료 대시보드에서 미낙찰(경매 종료·낙찰자 없음) 상품을 판매자가 **상시 판매로 전환(가격 지정)**
하거나 **경매 예정으로 되돌린다**. FE는 상품 등록에서 쓰던 것과 동일한 엔드포인트로 연결했다.

- 상시 판매 전환: `PATCH /api/products/{id}/status` body `{ price }`
- 경매 예정: `PATCH /api/products/{id}/auction-schedule`
- 등록 정보 표시: `GET /api/products/{id}`

## 확인 부탁

1. **미낙찰(경매 종료) 상품에도** 위 두 엔드포인트를 그대로 호출하면 되는지, 아니면 경매 종료 상품은
   **별도의 "복원" 선행 처리**가 필요한지. (상품 상태가 `경매종료/유찰` 같은 상태일 때 `/status`·
   `/auction-schedule` 호출이 허용되는지)
2. `PATCH /products/{id}/status { price }`가 상품을 **상시 판매(`DIRECT_SALE`) 상태 + 가격 지정**으로
   전환하는 것이 맞는지(등록 플로우의 DIRECT 판매와 동일 의미인지).

## 없는 API (필요 시)

- **등록 상품 내용 전체 수정**(제목·설명·카테고리 등) 엔드포인트가 없다(006 §5에서 "상품 수정 화면"
  보류로 언급). 현재 440에서는 **가격만** 수정/지정한다. 미낙찰 관리에서 상품 내용 전반을 고칠 수 있게
  하려면 상품 수정(`PATCH /api/products/{id}`) 계약이 필요하다.

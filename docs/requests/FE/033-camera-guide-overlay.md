# 의류 실측 촬영 가이드 오버레이 UI — 사전 공유

- **요청자 파트**: AI
- **대상 파트**: FE (경유: BE)
- **관련 티켓**: `S15P11A108-210` 에픽 하위(구체 이슈 번호 미정)
- **상태**: 요청 — BE가 상품 등록 흐름에 이 기능을 붙이는 결정이 먼저 필요해서(별도
  `.claude/requests/be/004-garment-measurement-scan.md` 참고), 지금 바로 착수하실 건 아니고
  UI 설계 시 참고하시라고 미리 공유드립니다.

## 배경

판매자가 상품 등록 시 찍는 옷 사진에서 어깨너비·소매길이 등을 cm 단위로 자동 추출하는 기능을
AI에서 만들고 있습니다. 사진 한 장만으로는 실제 크기(cm)를 알 수 없어서, **기준 물체(A4 용지)를
옷과 함께 위에서 내려다보는 각도(bird's-eye)로 촬영**해야 합니다 — 기준 물체의 실제 크기와
사진 속 픽셀 크기를 비교해서 스케일을 계산하는 방식입니다.

**기준 물체는 A4 용지입니다.** 신용카드도 후보였지만, 판매자가 실물 카드를 촬영해 서버로
올리는 흐름이라 번호·명의 등 개인정보 노출 위험이 있어 제외했습니다.

이 정확도는 촬영 품질에 크게 좌우됩니다 — 기준 물체가 잘려서 안 보이거나, 옷이 평평하게 안
펴져 있거나, 각도가 비스듬하면 결과가 나빠집니다. 그래서 촬영 시점에 화면에 가이드라인을
보여주는 UI가 필요합니다.

## AI가 받는 것 / 안 받는 것

- **AI는 최종 캡처 스냅샷 1장만 받습니다.** 프레임 스트림이 아닙니다.
- 실시간 웹캠 프리뷰에서 "기준 물체가 프레임에 잘 들어왔는지" 체크하는 건 **전적으로 FE
  클라이언트 사이드 몫**이고, 이 AI 백엔드 파이프라인과는 무관합니다 — 매 프레임을 서버로
  보내는 구조가 아닙니다.
- 사진이 조건(기준 물체 보임, 옷 평평함)을 만족 못 하면 AI는 `needs_retake: true` +
  이유(`retake_reason`)를 결과에 담아 돌려줍니다. 재촬영 유도 UX 자체는 FE가 정하시면 됩니다.

## 요청 내용

지금 바로 구현해 달라는 건 아니고, BE 쪽 상품 등록 연동 방식이 정해지면 그때 UI 작업을
잡아주시면 됩니다. 미리 고려해 두시면 좋을 것:

- 카메라 프리뷰 화면에 "여기에 A4 용지를, 여기에 옷을" 같은 가이드라인 오버레이
- **옷을 프레임 가장자리까지 꽉 채우면 안 됩니다.** 실사진으로 검증해보니, 서버 쪽 원단 분할
  알고리즘(GrabCut)이 "옷이 화면 중앙 쪽, 테두리에서 일정 여백 안에 있다"고 가정합니다 —
  소매를 펼쳤을 때 소매 끝이 가장자리에 닿거나 잘리면 그 부분이 배경으로 인식돼 분할 결과에서
  빠집니다. 가이드 오버레이에 "옷 전체(소매 끝 포함)가 안쪽 사각형 안에 들어오도록 조금 더
  멀리서 찍으라"는 취지의 안내선/여백을 포함해 주세요.
- A4 용지가 프레임에 들어왔는지 실시간 체크 — **AI 모델이 필요 없습니다.** 흰 사각형 종이의
  윤곽(엣지/컨투어)만 잡으면 되는 수준이라 전통 CV로 충분합니다(서버 쪽 기준 물체 검출도
  같은 이유로 학습 모델 없이 OpenCV 컨투어 검출만 씁니다 — `registry.py`의 `opencv_contour`
  백엔드). 클라이언트 사이드(OpenCV.js/WASM 등)에서 처리하시면 되고, 서버 왕복도 필요 없습니다.
- `needs_retake`/`retake_reason`을 받았을 때의 재촬영 유도 UX

# 031 방송 종료 요약·유찰 목록 계약 (Phase 8-b)

- **작성자 파트**: BE (정윤) / **대상 파트**: FE
- **작성일**: 2026-08-05
- **원 요청**: `docs/requests/BE/018-live-broadcast-end-summary.md`(방송 종료 요약),
  `docs/requests/BE/007-unsold-product-disposition.md`(미낙찰 상품 처리)

방송 종료 대시보드(`-438`)와 미낙찰 상품 처리(`-440`)가 기다리던 조회 2개가 나왔습니다.
둘 다 **호스트 본인만** 볼 수 있습니다(판매 실적이라 시청자에게 공개하지 않습니다).

## 1. `GET /api/lives/{liveId}/summary` — 방송 종료 요약

`LiveBroadcastPage.vue`의 `broadcastSummary` 하드코딩을 이걸로 바꾸시면 됩니다.

```jsonc
{
  "soldCount": 3,
  "unsoldCount": 2,
  "totalSales": 452000,
  "results": [
    {
      "productId": 2001,
      "title": "리바이스 501 빈티지",
      "thumbnailUrl": "https://.../2001.jpg",
      "status": "SOLD",          // SOLD | UNSOLD
      "finalPrice": 89000,       // 안 팔렸으면 null
      "soldVia": "AUCTION"       // 안 팔렸으면 null
    }
  ]
}
```

- **`results`는 편성 상품 전체가 기준**이고 편성 순서를 그대로 따릅니다. **경매를 아예 걸지 않은
  편성 상품도 `UNSOLD`로 들어옵니다** — 대시보드가 방송 전체를 보여 줘야 하기 때문입니다.
- 방송이 끝나기 전에 불러도 200이며 그 시점까지의 결과를 줍니다.
- 요청서에 없던 `title`/`thumbnailUrl`을 넣었습니다. `results`만으로 카드를 그릴 수 있게 하려는
  것이고, 상품 상세를 따로 부를 필요가 없습니다.

### ⚠️ 즉시구매를 집계에 넣으려면 `liveId`를 보내 주셔야 합니다

요약은 **경매 실적이 아니라 방송 실적**이라, 방송 중 정찰가로 팔린 것도 함께 셉니다
(`soldVia`가 `AUCTION` / `DIRECT_SALE`로 구분됩니다).

그런데 **주문만 봐서는 어느 방송에서 팔렸는지 알 수 없습니다.** 그래서
`orders`에 `live_id`를 추가하고, 주문 생성 요청에 선택 필드 `liveId`를 열었습니다.

```jsonc
// POST /api/orders — 라이브 시청 화면에서 구매할 때
{
  "productId": 2003,
  "liveId": 101      // ← 신규(선택). 라이브 밖에서 사면 생략
}
```

- **`liveId`를 안 보내면 그 판매는 방송 요약에 안 잡힙니다.** 라이브 시청 화면에서 구매 버튼을
  붙이실 때 꼭 실어 주세요.
- 라이브 밖(상품 상세 등)에서 사는 경우는 생략하시면 됩니다. 기존 호출은 그대로 동작합니다.
- 없는 방송 ID를 보내면 404입니다(조용히 무시하면 요약에서 빠진 이유를 알 수 없어서입니다).
- 경매 낙찰 주문은 서버가 알아서 방송을 채우므로 FE가 할 일이 없습니다.
- 환불·취소된 주문은 판매액에서 빠집니다.

## 2. `GET /api/lives/{liveId}/unsold-products` — 방송별 유찰 상품

"남은 상품 관리" 화면에 쓰시면 됩니다.

```jsonc
[
  {
    "productId": 2002,
    "title": "울 코트",
    "thumbnailUrl": "https://.../2002.jpg",
    "startPrice": 10000    // 이 방송에서 마지막으로 걸었던 경매의 시작가
  }
]
```

- **상품 판매 상태로 거르지 마세요.** 유찰 상품은 판매 상태가 `AUCTION_SCHEDULED`로 돌아가기
  때문에, 상태만 보면 **다른 방송에서 유찰됐거나 아직 한 번도 경매에 안 걸린 상품까지 섞입니다.**
  "이 방송에서 안 팔렸다"는 사실은 서버만 알 수 있어 이 API로 뺐습니다.
- 같은 상품에 재경매를 걸었다면 **마지막 경매 결과만** 봅니다 — 유찰 뒤 다시 걸어 낙찰됐으면
  이 목록에 안 나옵니다.
- 경매를 아예 안 건 편성 상품은 여기 없습니다. 방송 전체를 보시려면 §1을 쓰세요.
- `startPrice`는 재경매 기본값으로 그대로 쓰시면 됩니다.

---

## 3. 유찰 상품도 이제 내용 수정이 됩니다 (007 해소)

`PATCH /api/products/{id}`가 `DRAFT`/`ON_SALE`에서만 되던 것을 **`AUCTION_SCHEDULED`까지 허용**하도록
바꿨습니다. 유찰 상품은 이 상태로 돌아오므로, "안 팔렸으니 설명·사진 고쳐서 다시 걸자"가 이제
그대로 됩니다. 상시 판매로 전환했다가 되돌리는 우회로가 필요 없습니다.

- **경매가 진행 중인 상품(`AUCTION_IN_PROGRESS`)은 계속 막힙니다.** 입찰이 붙는 도중에 상품
  정보가 바뀌면 입찰자가 보고 판단한 것과 달라지기 때문입니다. `SOLD`도 마찬가지입니다.

## 4. 시청자 수에서 호스트를 뺐습니다

기존에는 **판매자가 자기 방송 화면을 열면 그 세션도 시청자 1명으로 잡혔습니다.** 아무도 안 보는
방송이 항상 "1명"으로 보이고, 판매자가 "몇 명이 보고 있나"를 볼 때 자기 자신을 빼서 읽어야 했습니다.
이제 호스트는 세지 않습니다 — **판매자만 들어와 있으면 0명입니다.**

적용 범위는 시청자 수가 나가는 모든 경로입니다.

| 경로 | 필드 |
| --- | --- |
| `/topic/lives/{liveId}/viewers` 실시간 | `viewerCount` |
| `GET /api/lives/{liveId}` | `currentViewerCount`, `peakViewerCount` |
| `GET /api/lives` (목록) | `viewerCount` |
| `GET /api/home` (홈 카드) | `viewerCount` |

- 최고 시청자 수(`peakViewerCount`)도 같은 기준입니다.
- **판매자도 남의 방송에서는 시청자로 셉니다** — 자기 방송에서만 빠집니다.
- 비회원 시청자는 그대로 셉니다.

> ⚠️ **`028` §4의 중복 집계 건은 아직 FE 쪽에 남아 있습니다.** 라이브 시청 화면이 STOMP 연결을
> 2개(`LiveWatchPage.vue` + `LiveChatOverlay.vue`) 열고 있어 시청자 1명이 2명으로 잡히는 문제입니다.
> 이건 세션 단위 집계라 BE가 구분할 수 없어 연결을 하나로 합쳐 주셔야 합니다. 이번 호스트 제외와는
> 별개 건입니다.

## 5. 라이브 즉시구매 구현 시 체크리스트

라이브 시청 화면에 구매 버튼을 붙이실 때 확인해 주세요.

- [ ] `POST /api/orders`에 **`liveId`를 함께 보낸다** (§1 참고). 이게 빠지면 판매가 방송 요약에
      안 잡힙니다.
- [ ] 구매 대상은 **`saleType`이 `DIRECT_SALE`이고 `saleStatus`가 `ON_SALE`인 상품**만입니다.
      경매 상품(`AUCTION_SCHEDULED`/`AUCTION_IN_PROGRESS`)은 400입니다 — 라이브 상품 큐에
      두 종류가 섞여 있으니 버튼 노출을 `saleType`으로 갈라 주세요.
- [ ] 본인 상품은 살 수 없습니다(400). 호스트 화면에서는 구매 버튼을 숨기시면 됩니다.
- [ ] 결제는 포인트 차감입니다. 잔액이 모자라면 400(`W001`)이며 충전 안내가 필요합니다.

현재 라이브 상품 카드의 액션이 "상품 상세 보기"·"찜" 둘뿐이라 아직 구현 전으로 보고 스키마만
먼저 열어 뒀습니다. 붙이신 뒤 요약에 안 잡히면 `liveId` 누락부터 확인해 주세요.

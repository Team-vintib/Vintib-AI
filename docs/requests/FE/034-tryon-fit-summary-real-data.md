# 가상 시착 결과 — "한 줄 핏 예상" 목업 → 실제 데이터 전환 요청

- **요청자 파트**: AI
- **대상 파트**: FE
- **관련 티켓**: `S15P11A108-210` 에픽 하위, `S15P11A108-567`

## 배경

`FE/src/domains/tryon/constants/liveTryOnMockData.ts`의 `fitTitle`/`fitDescription`이
지금 하드코딩돼 있는 걸 확인했습니다(`'M 사이즈가 적합합니다.'` / `'어깨와 가슴 부분에
약간 여유 있는 핏이 예상됩니다.'`). AI 쪽에 이 값을 실제로 계산하는 로직을 구현·검증
완료했고, BE에도 시착 결과 응답에 이 필드를 포함해달라고 별도 요청했습니다
(`docs/requests/BE/038-tryon-fit-summary-fields.md`).

## 요청 내용

BE 쪽 반영이 끝나면, 시착 결과 API 응답의 `fitTitle`/`fitDescription`(또는 BE가 정한
실제 필드명 — snake_case로 올 수 있으니 확인 필요)을 지금 목업 대신 그대로 바인딩해
주시면 됩니다. 문구 형식은 목업과 동일합니다(제목 한 줄 + 근거 한 문장).

**두 값 다 `null`이거나 응답에서 아예 빠질 수 있습니다.** 회원이 신체 정보(키/몸무게 등)를
등록 안 했거나, 상품에 실측 사이즈가 없으면 AI가 예측 자체를 못 해서 값을 안 보냅니다 —
이 경우 "핏 예상" 영역을 숨기거나 "핏 예상 정보가 없어요" 같은 폴백 문구를 보여주시면
됩니다. 지금 목업처럼 **항상 값이 있다고 가정하면 안 됩니다.**

## 실제 문구 예시 (참고용)

- `"선택하신 사이즈가 살짝 타이트해요."` / `"허리 부분이 몸에 붙는 타이트한 핏으로 예상돼요 (기준보다 약 27% 작아요)."`
- `"선택하신 사이즈가 적당해요."` / `"가슴과 어깨 부분이 몸에 잘 맞는 기본 핏으로 예상돼요."`
- `"선택하신 사이즈가 넉넉한 오버사이즈예요."` / `"가슴과 어깨 부분에 여유가 많은 오버사이즈 핏으로 예상돼요 (기준보다 약 38% 커요)."`

## 1. `LiveProductResponse` 선택 필드 3종 (003 §3.5)

```jsonc
{
  "productId": 2001,
  // ... 기존 필드 ...
  "material": "코튼 100%",           // 신규. 없으면 null
  "measurements": { "어깨너비": 45, "총장": 70 },  // 신규. 없으면 null
  "defectSummary": "밑단 오염, 우측 소매 실밥 풀림"  // 신규. 없으면 null
}
```

- `material`/`measurements`는 상품 등록 시 입력한 값을 그대로 내립니다.
- `defectSummary`는 **목록이 아니라 한 줄 요약**입니다. 등록된 하자 항목을 쉼표로 이어 붙였습니다.
  상세 목록이 필요하면 상품 상세(`GET /api/products/{id}`)를 여세요 — 그쪽엔 이미
  `defects[]` 형태로 있습니다.
- 셋 다 편성 상품 수만큼 상품 상세를 더 읽지 않고, 시청 화면 상품 목록 조회 한 번에 같이 옵니다.

`LiveDetailResponse.hostProfileImageUrl`/`description`은 지난 배치(022)에서 이미 반영됐습니다 —
그 문서에 "아직 없음"으로 잘못 적혀 있던 걸 이번에 바로잡았습니다(003 문서 참고).

## 2. 알림 2종 신규 (004 §3.2)

지금까지 실제로 알림을 만드는 경로는 `LIVE_REMINDER`(예약 라이브 알림) 하나뿐이었습니다.
여기에 두 개를 더했습니다 — 둘 다 제 도메인(라이브·경매)에서 트리거되는 이벤트라 서윤을 기다리지
않고 바로 넣었습니다.

| type | 트리거 시점 | refType/refId | title/body |
| --- | --- | --- | --- |
| `LIVE_STARTED` | 팔로우한 판매자의 방송이 시작될 때(즉시 개설 직후, 또는 예약 방송이 `LIVE`로 전이될 때) | `LIVE` / liveId | "{판매자}님이 라이브를 시작했어요" / 방송 제목 |
| `AUCTION_OUTBID` | 내가 최고 입찰자였는데 다른 사람이 더 높은 금액으로 입찰했을 때 | `AUCTION` / auctionId | "상위 입찰이 발생했어요" / "다른 사용자가 더 높은 금액으로 입찰했습니다." |

- `LIVE_STARTED`는 그 판매자를 팔로우하는 **모든 회원**에게 갑니다(최대 500명 — 그 이상은 다음
  요청 때 비동기 발송으로 옮길 계획입니다. 지금 규모에서는 사실상 전원에게 갑니다).
- `AUCTION_OUTBID`는 밀린 사람 한 명에게만 갑니다. 첫 입찰(아직 아무도 안 밀림)에는 발송되지
  않습니다.
- `AUCTION_WON`(낙찰 알림)은 아직입니다 — 경매 종료 자체가 다음 단계(Phase 8, `-467`)라 그때
  함께 붙입니다.

이제 로컬 `notification` 테이블에 `LIVE_STARTED`/`AUCTION_OUTBID` 값이 실제로 생성되니, 004
문서에 남아 있던 "실제 알림 생성 이벤트가 없어 시연 데이터가 없다"는 문제가 이 두 종류에서는
해소됩니다. 나머지 5종(`ORDER_PAID`/`SHIPMENT_*`/`POINT_*`)은 주문·포인트 도메인이라 제 담당이
아니라 그대로 남아 있습니다 — 서윤 확인이 필요합니다.

## 3. 미낙찰 상품 처리 — 예비 답변 (007 §확인 부탁 1)

007에서 "경매 종료 상품에도 `/status`·`/auction-schedule`을 그대로 호출하면 되는지"를 물으셨습니다.
경매 종료(Phase 8)가 아직 코드로는 없지만, **DB 설계는 이미 확정돼 있어** 미리 답할 수 있습니다.

- 유찰(입찰자 없이 종료)이면 상품은 **자동으로 `AUCTION_SCHEDULED`로 되돌아갑니다** — 별도의
  "복원" API가 필요 없습니다. 그대로 두면 다음 라이브에서 다시 경매에 걸 수 있고, `/status`를
  호출하면 상시 판매로 전환됩니다.
- `ck_product_price_by_type` 제약은 "상시 판매엔 가격이 있어야 한다"만 강제하고 경매 상품에
  가격이 들어가는 것은 막지 않아서, **어느 순서로 호출해도 안전합니다.**

즉 FE가 이미 연결해 두신 두 엔드포인트를 **그대로 쓰시면 됩니다.** 다만 이건 설계 문서 기준
예비 답변이고, Phase 8 코드가 실제로 들어가면 다시 한번 확인해 드리겠습니다.

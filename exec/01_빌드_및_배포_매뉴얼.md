# VINTIB 빌드 및 배포 매뉴얼

GitLab 소스클론 이후 빌드·배포까지 그대로 따라 할 수 있도록 정리한 문서다. 실제 배포는
GitLab CI/CD가 `main` 브랜치 병합 시 자동으로 수행하며, 로컬/수동 재현 절차도 함께 적는다.

## 1. 사용 제품 종류·버전·설정값

레포지토리에 고정되어 있지 않다 — 시연 환경에서 실제 사용한 IDE명·버전을 이 표에 덧붙여
기재할 것(BE 확인 필요 아님, 발표 팀 직접 기재).

### 1-2. 리소스/포트 설정값

- 메모리 예산(EC2 15GB): backend 3g, ai 1g, postgres 2g, postgres-vector 512m, redis 1g,
  minio 1g, livekit 1g, caddy 512m, frontend 256m (`docker-compose.yml`/`docker-compose.prod.yml`
  각 서비스 `mem_limit`)
- JVM 힙: `-Xmx2g` (`BE/Dockerfile`의 `JAVA_OPTS`)
- 외부 노출 포트(운영, EC2): `443`(Caddy, TCP+UDP/HTTP3), `80`(LiveKit 미디어 TCP 전용 —
  SSAFY 상위 방화벽이 22/80/443/8989만 통과시켜 미디어에 80을 내줌), `7885/udp`(현재 상위
  방화벽에 막혀 미사용). 그 외 backend/postgres/redis/ai/minio는 호스트 포트를 열지 않는다
  (`docker-compose.prod.yml` 주석 참고 — Docker가 포트 publish 시 iptables를 직접 조작해
  UFW를 우회하는 문제를 피하기 위함).
- 로컬 개발 전용 포트(운영에는 없음): DB 5432, pgvector 5433, Redis 6379, backend 8080,
  ai 8000, LiveKit 7880/7885, MinIO API 9000 / 콘솔 9001 (`docker-compose.override.yml`)

## 2. 빌드 시 사용되는 환경 변수

### 2-1. 빌드 타임(이미지 빌드에 영향)

| 대상 | 환경변수 | 설명 |
| --- | --- | --- |
| FE | `.env.production` 파일 (env var 아님) | `vite build`(production 모드)가 자동 로드. `VITE_API_BASE_URL=/api` 등 — 값은 `FE/.env.production` 참고 |
| BE/AI | 없음 | 소스 컴파일(`gradlew bootJar`)·의존성 설치(`pip install`)에 빌드타임 환경변수를 쓰지 않는다 |

### 2-2. 런타임(컨테이너 기동 시 주입, `.env` → `docker-compose.yml`)

`.env.example`을 `.env`로 복사해 채운다(`cp .env.example .env`). 주요 그룹:

- DB/Redis: `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `VECTOR_DB_*`, `REDIS_PORT`/`REDIS_PASSWORD`
- Spring: `SPRING_PROFILES_ACTIVE`(local/prod), `SERVER_PORT`, `JWT_SECRET`,
  `JWT_ACCESS_TOKEN_EXPIRATION`, `JWT_REFRESH_TOKEN_EXPIRATION`
- 스토리지(MinIO/S3 호환): `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`(볼륨 최초 생성 시 값으로
  고정됨 — 나중에 바꾸려면 볼륨 삭제 필요), `AWS_S3_*`
- 미디어(LiveKit/OpenVidu): `OPENVIDU_API_KEY`/`OPENVIDU_API_SECRET`(백엔드·livekit 컨테이너가
  반드시 동일한 값을 사용), `OPENVIDU_SERVER_URL`, `LIVEKIT_NODE_IP`(운영 전용, EC2 공인 IP)
- 메일: `MAIL_HOST`/`PORT`/`USERNAME`/`PASSWORD` (Gmail SMTP, 앱 비밀번호 사용)
- 결제: `TOSS_SECRET_KEY`/`TOSS_CLIENT_KEY`
- 배송 조회: `DELIVERY_API_KEY`/`SECRET_KEY`/`ENDPOINT_ID`/`WEBHOOK_SECRET`
- 구글 로그인: `GOOGLE_OAUTH_CLIENT_ID`/`SECRET`
- AI 가격 책정: `GMS_API_KEY`, `NAVER_CLIENT_ID`/`SECRET`, `PRICING_COMPS_SOURCE`(기본 mock),
  `PRICING_ATTRIBUTE_EXTRACTOR`(기본 regex)
- AI 워커 인증: `WORKER_API_KEY` (AI 게이트웨이 ↔ 워커 내부 인증)
- 배포 이미지 태그: `IMAGE_TAG` (CD 파이프라인이 커밋 SHA로 자동 설정)

전체 변수와 각 값의 의미·기본값(폴백 여부)은 `.env.example` 주석에 상세히 설명되어 있다.

## 3. 배포 시 특이사항

- **배포 트리거는 `main` 브랜치 하나뿐이다.** `feat/* → develop-{BE,FE,AI} → main` 순으로
  머지되며, `main` 병합 시 GitLab CI가 EC2에 자동 배포한다(`.gitlab-ci.yml`의 `deploy` job,
  전용 러너 `tag: deploy`). 파트별 `develop-*` 브랜치를 배포 트리거로 걸면 안 된다 — 나중에
  배포하는 파트가 항상 다른 파트를 롤백시키기 때문이다.
- 배포 스크립트는 `infra/ci/deploy.sh`: ① 저장소 전체를 EC2 `/home/ubuntu/vintib`로 rsync
  ② GitLab CI/CD Variables로 `.env` 생성 ③ `docker compose -f docker-compose.yml
  -f docker-compose.prod.yml build && up -d` ④ Caddy 설정 파일 해시를 비교해 필요 시 재시작
  ⑤ backend 헬스체크(최대 180초) ⑥ 실패 시 직전 이미지 태그로 자동 롤백.
- `.env`는 저장소에 커밋하지 않는다. 운영 값은 GitLab **Settings → CI/CD → Variables**에
  `PROD_` 접두사로 등록한다(필수 변수 목록은 `.gitlab-ci.yml` `deploy` job 상단 주석 참고).
  필수 변수가 비어 있으면 `.env`를 만들기 전에 배포가 즉시 실패한다(조용히 잘못된 값으로
  배포되는 것을 방지).
- EC2 운영 기동은 반드시 `-f docker-compose.yml -f docker-compose.prod.yml`을 명시한다.
  `docker-compose.override.yml`(로컬 전용, DB/Redis 포트 개방)이 병합되면 안 되므로,
  배포 스크립트가 해당 파일을 `_disabled/`로 격리한다.
- **PostgreSQL / MinIO 자격증명은 볼륨을 처음 만들 때의 값으로 고정된다.** 이후
  `DB_PASSWORD`/`MINIO_ROOT_USER`/`PASSWORD`를 바꾸면 컨테이너가 기존 볼륨과 인증이 어긋난다
  — 볼륨을 지우거나(=데이터 유실) DB 내부에서 `ALTER USER`로 맞춰야 한다.
- **LiveKit `NODE_IP`(=`LIVEKIT_NODE_IP`)는 EC2 공인 IP를 반드시 채운다.** 비우면 컨테이너
  사설 IP를 ICE 후보로 broadcast해 브라우저가 미디어에 붙지 못한다 — 에러 없이 방송 화면만
  검게 나오는 형태라 원인 파악이 어렵다.
- BE 타임존은 `TZ=Asia/Seoul`로 고정(Dockerfile에 하드코딩). 모든 시각 필드가 오프셋 없는
  `LocalDateTime`(KST 벽시계)이라 서버가 UTC로 돌면 시각이 9시간 어긋난다.
- Caddyfile은 **디렉터리** 단위로 bind mount 한다(파일 단위 mount는 rsync의 rename 교체 후
  inode가 바뀌어 `caddy reload`가 옛 설정을 계속 읽는 문제가 있었음). 배포 스크립트가 호스트
  파일과 컨테이너 내부 파일의 md5sum을 비교해, 다르면 reload 대신 컨테이너를 재시작한다.
- 이 EC2 서버는 SSAFY Gerrit(8988/8989/29418)과 같은 호스트를 공유한다 — 새 포트를 열 때
  해당 포트들과 22/80/443을 침범하지 않는다.

## 4. DB 접속 정보 등 주요 계정·프로퍼티가 정의된 파일 목록

| 파일 | 내용 |
| --- | --- |
| `.env.example` | 로컬 개발용 전체 환경변수 템플릿 (DB/Redis/스토리지/외부 API 키 등) — `.env`로 복사해서 사용 |
| `docker-compose.yml` | 각 서비스(postgres/postgres-vector/redis/minio/backend/ai)의 접속 정보를 컨테이너 환경변수로 정의 |
| `docker-compose.override.yml` | 로컬 전용 호스트 포트 매핑 (DB 5432, pgvector 5433, Redis 6379 등) |
| `docker-compose.prod.yml` | 운영 전용 오버레이 — Caddy/LiveKit 포트, `SPRING_PROFILES_ACTIVE=prod` |
| `BE/src/main/resources/application.yml` | Spring datasource(JDBC URL)·Redis·메일·JWT·외부 API(OpenVidu/배송/토스/구글) 설정 키와 기본값 |
| `BE/src/main/resources/application-local.yml`, `application-prod.yml` | 프로필별 오버라이드 |
| `AI/app/core/config.py` | AI(FastAPI) `pydantic-settings` 기반 설정 클래스 — DB/벡터DB/Redis/외부 API 키 필드와 기본값 |
| `FE/.env.example`, `FE/.env.production` | FE 빌드 타임 환경변수(`VITE_*`) — API Base URL, 기능 플래그 |
| `infra/ci/deploy.sh` | 운영 `.env` 생성 로직 — GitLab CI/CD Variables → `.env` 매핑 관계의 단일 소스 |
